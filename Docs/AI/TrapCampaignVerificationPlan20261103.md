## 후속 플레이 검증

사용자 “그럼 검증해줘” 승인으로 실제 프레임·입력·준비 저장 왕복·원본 저장 호환 복원과 제한된 비교 관찰을 수행했다. 이어 “다음 작업 해줘” 요청으로 보스 밀치기 1.05칸과 낙석 입력/피해·대기/대상 제외를 통제된 런타임에서 확인했다. [실측 결과와 남은 항목](TrapCampaignPlayVerification20261103.md)을 따른다. 아래 금지/미실행 표현은 당시 제한 실행의 이력이며 이번 승인 범위에는 적용하지 않는다. 전체 캠페인 완주·최종 밸런스는 아직 아니다.

## 제한 실행 결과

아군 피해 후속 확인: 범위형/지속형 2개를 별도로 실행해 2/2 통과했다. 범위 안 적/아군 피해, 범위 밖 적/아군 제외, 공통 배율과 적 전용 배율의 분리를 실제 함정 처리에서 확인했다. 첫 지속형 기대값 오류는 1초 틱 규칙에 맞춰 검사만 고쳤다. 근거는 tmp/trap-friendly-fire-results.json이며 게임 수치/런타임 코드는 변경하지 않았다.

후속 통합 확인: StagePush_Integration 검사 5개를 추가해 **5/5 통과**했다. 실제 함정 접촉→발동→체력 피해 경로의 밟기/범위/지속형, 다중 칸 중복 방지와 도중 처치 후 정지를 확인했다. 근거는 tmp/trap-contact-integration-results.json이며 아래 최초 27개 실행과는 별도 실행이다. 실제 입력/처치 보상 정산/플레이/사용자 저장 왕복/밸런스는 포함하지 않는다.

사용자 "관련 EditMode 검사만 실행" 승인으로 아래 대상만 실행했다. 최종 **27개 발견/27개 통과/실패 0/무시 0**이다. 첫 실행의 JSON 호환 실패 1개를 수정한 뒤 관련 전체를 다시 실행했다. 추가한 잘못된 방향 목록 개수 검사 2개도 포함한다.

| 묶음 | 최종 통과/실행 |
|---|---|
| 밀치기·파티 | 7/7 |
| 수동 장치 발동 보호 | 3/3 |
| 준비 저장 JSON·본편 선택 | 8/8 |

Unity는 JSON의 누락된 방향 목록을 null 대신 빈 목록으로 읽었다. StageDevices의 검증/복원은 null·빈 목록을 모두 맵 기본 방향으로 처리하며, 비어 있지 않은 잘못된 목록은 상태를 변경하지 않고 거절한다. 기존의 null 자체를 요구하던 검사는 실제 기본 방향 복원 동작을 확인하도록 바꿨다.

근거는 `tmp/trap-editmode-verification-20261103/`의 initial-*.json, final-*.json, summary.json과 최종 build-*.log다. Runtime/Editor/Tests 빌드·Unity 재컴파일 오류 0, 최종 Editor ready/stopped·콘솔 오류 0을 확인했다. 플레이·실제 사용자 저장 입출력 왕복·밸런스는 계속 미실행이다.

## 현재 확인한 범위

코드 빌드/Unity 재컴파일·편집 모드 에셋 배선과 위의 제한된 회귀 검사를 확인했다. 나머지 테스트·Play/Stop·실제 저장 왕복·밸런스 실측은 금지 상태다. 아래의 대상 목록을 벗어난 실행 허가로 해석하지 않는다.

이번 정적 점검에서 타이틀/준비 HUD의 정상 재도전·이전/다음 스테이지 경로는 SelectStage 뒤 ChooseBarricade로 도구를 초기화하는 것을 확인했다. 단순 HUD 재활성화는 기존 선택을 유지하는 수명 계약을 따른다. 추가 런타임 수정은 하지 않았다.

## 첫 실행 대상 — 허용 후 EditMode만

전체 과거 테스트를 한꺼번에 실행하기 전에 아래 메서드를 대상으로 필터를 구성한다. 실제 도구의 필터 형식을 확인하고, 결과 파일에 발견/실행/실패/무시 수를 남긴다. 0개 발견을 성공으로 기록하지 않는다.

| 순서 | 위치와 메서드 | 통과 기준 |
|---|---|---|
| 1 | TrapTileTests의 StagePush_ 메서드 | 중간 칸 접촉, 미리보기 무부작용, 도중 처치 시 정지, 닫힌 문 통과 금지, 리더 경로 재시작, 멤버의 열린 길 합류, 조회 재진입 보호 |
| 2 | TrapTileTests의 StageDevice_ 메서드 | 같은/다른 장치의 중첩 발동 거절, 발동 종료 후 정상 순차 사용, 예외 시 잠금 해제와 재사용 대기 보존 |
| 3 | IntrusionAndSaveTests의 StageCheckpoint_ 및 StageDevice_CheckpointSignaturePreservesLegacyFieldsAndTracksNewDevices | 구 JSON 누락 필드, 방향/함정 상태 직렬화, 잘못된 방향 거절, 정확한 맵 서명에 따른 카탈로그 선택, 기존 장치 서명 호환 |
| 4 | AssetWiringTests의 TrapLab_ 및 TrapCampaign_ 메서드 | 본편/실험 분리, 맵/ID 보존, 닫힌 문 우회 경로, 장치 조합, 빈 발동 비용 없음, 회전 방향 유지 |

필터 대상은 Assets/Tests/EditMode/Reflected의 기존 세 파일에 있다. 각 묶음은 사용자 프로필/준비 저장의 실제 파일을 읽거나 쓰지 않는 대상으로 한정한다. 관련 없는 파일 저장/구 경영 테스트는 포함하지 않는다. 실패하면 해당 실패와 연결된 코드만 수정하고 관련 묶음을 다시 확인한다.
