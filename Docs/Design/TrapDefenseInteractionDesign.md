# 함정 설계와 직접 발동 중심 방어

2026-11-03 사용자 방향 확정. 현재 스테이지 방어를 Dungeon Warfare의 동선·함정 설계와 Orcs Must Die의 함정 활용·직접 개입에서 느낀 재미에 가깝게 발전시킨다. TrapLab 첫 구현에 이어 본편 7개 스테이지까지 전환했다. 원래 본편 데이터는 기존 저장 호환용으로 보존한다. 아래에서 채택한 구현과 이전 제안을 구분한다.

## 2026-11-03 함정 본편 HUD 재설계 (목업 확정, 구현 전)

사용자: 화면 확인 뒤 "ui 배치나 그런게 가독성도 부족하고 너무 ai같아" → A안(하단 단축칸형)을 던전 워페어식 배치로 다듬어 확정. 원인 진단: 모든 정보가 점(·)으로 이은 문장, 버튼·패널 무게가 같음, 바탕 없이 뜬 글자, 맵이 화면 절반, 설명이 늘 펼쳐짐. 원본 StageDefense HUD는 바꾸지 않는다.

- 전투 화면
  - 위 한 띠: 코어 체력 막대·금화·웨이브와 진행 막대·남은 적 / 오른쪽 끝 일시정지·배속·설정.
  - 아래 가운데 단축칸: 바닥 함정 / 벽 함정 / 도구(바리케이드 Q·철거 X) 세 묶음, 묶음 위 이름표. 함정 칸은 숫자키 1~4, 아이콘·가격, 금화 부족이면 어둡게.
  - 놓은 함정을 누르면 둘레에 강화(비용)·판매(환급)·회전 둥근 버튼과 단계 점(●●○). R·E 키는 유지.
  - 왼쪽 아래 부하 초상(체력·궁극기 막대, 쓰러지면 어둡게 "복구").
  - 오른쪽 아래 수동 장치 둥근 버튼(재사용 시계·남은 초, Space). 기본안: 마지막으로 고른 장치를 발동, 맵에서 장치를 누르면 그 장치를 고른다.
  - 적 예고는 맵의 문 위 해골+숫자. 맵이 화면 대부분을 쓰게 카메라를 맞춘다.
- 준비 단계 오른쪽 아래: 상인·웨이브 시작. 재도전·타이틀은 설정 창 안으로.
- 스테이지 시작 전 편성 창: 함정·부하 전체 아이콘 격자, 고르면 오른쪽에 설명·영구 강화, 아래 가져갈 4칸·유물, "출격". 첫 웨이브 뒤 편성 고정 규칙과 맞춘다.
- 넣지 않음: 다음 웨이브 일찍 부르기 보너스(규칙 변경이라 별도 결정).
- 아이콘 재료: 바닥 함정은 프리팹 그림, 부하는 초상(UnitDataSO.IconSprite)이 있다. 벽 함정·수동 장치는 그림이 없어 UI 팩 기호나 임시 그림이 필요하다.
- 키(사용자 확정): 함정 1~8, 바리케이드 Q, 철거 X, 수동 장치 F. 함정 본편만 배속을 F1·F2로 옮기고(GameSpeedController.functionKeySpeeds) Space 일시정지는 유지한다.
- 구현 단계: 1 위 띠·단축칸·버튼 정리·카메라 → 2 시작 전 편성 창 → 3 둥근 강화·판매 메뉴 → 4 부하 초상·수동 장치 버튼.

### 1단계 구현 결과 (2026-11-04, 플레이 화면 확인)

- StageTopBand(위 한 띠), StageHotbar·StageHotbarSlot(바닥 8·벽 8·도구 2칸, 편성 함정만 채우고 빈 묶음은 "없음" 한 칸, 금화 부족·사용 불가는 어둡게). StageStatusBar와 브리핑·안내 줄은 지웠다.
- StageHudView: 새 칸이 있으면 띠·단축칸을 그리고, 편성 패널은 준비 단계에만 보이며, 전투 중 알림(가운데 위)은 경고·상황 한 줄만 적는다. 준비 단계 제목 아래 둘째 줄에 적 예고·규칙. 도구 줄은 단축칸 위 짧은 한 줄. 재도전은 설정 창을 닫고 실행한다.
- StageMapView.hudFraming: 위 7.5%·아래 14%를 비우고, 편성 패널이 열리면 왼쪽 23%를 비운다(0.3초 동안 옮김).
- 생성기 StageHudPolishBuilder: 편성 패널을 띠 아래(80)로, 바리케이드·철거 버튼은 숨김(단축칸이 맡음), 배속·설정을 띠 오른쪽, 상인·보급품·웨이브 시작을 오른쪽 아래, 재도전을 설정 창의 다시 시작 자리로, 타이틀 버튼은 숨김. 작은 편성 줄의 해제 버튼 글자를 13으로.
- 남은 점: 편성 패널의 바리케이드·철거 빈자리(2단계 편성 창이 대신함), 벽 함정은 두 글자 이름 칸(그림 없음).

### 2단계 구현 결과 (2026-11-04, 플레이 화면 확인)

- StageLoadoutWindow·StageLoadoutCell: 가운데 1240×760 창(뒤를 어둡게 덮어 맵 클릭을 막음). 5열 격자(그림·이름·가격, 잠기면 "N 스테이지 클리어"), 편성에 든 칸은 금색·고른 칸은 파란 테두리. 오른쪽 설명(기준값·영구 강화 단계)과 "편성에 넣기/빼기"·"영구 강화 · 재화 N". 아래 가져갈 칸(슬롯 수만큼, 누르면 뺌)·유물 요약/버튼·상태 줄·출격. 규칙은 StageSession.ToggleOption·TryUpgrade 그대로.
- 첫 웨이브 전 준비 단계에 들어올 때 스테이지마다 한 번 저절로 열리고(재도전하면 다시 연다), 오른쪽 아래 "편성" 버튼으로 다시 연다. 첫 웨이브 뒤에는 버튼을 숨기고 창을 닫는다.
- 왼쪽 편성 패널은 쓰지 않는다(맵이 늘 화면 너비). 스테이지 이동·편성 수·유물 요약/버튼은 패널의 기존 요소를 창으로 옮겨 HUD 배선을 그대로 쓴다. 제목·적 예고는 왼쪽 위, 알림(상황 한 줄)은 오른쪽 위.
- 단축칸에 부하 묶음(왼쪽 아래, 준비 단계·편성한 부하가 있을 때만)을 더했다. 그림은 StageOptionIcons(부하 초상·바닥 함정 프리팹)가 찾는다.
- 적 예고 줄은 커서가 놓을 수 없는 칸에 있어도 남긴다.
- 생성기는 두 번 돌려도 창·버튼이 하나씩이고 옮긴 요소가 창 안에 남는 것을 확인했다.

### 4단계 구현 결과 (2026-11-04, 플레이 화면 확인)

- StageUnitPortraits·StageUnitPortrait: 전투 중 왼쪽 아래(준비 단계 부하 단축칸 자리)에 배치한 부하 초상 최대 6칸. 체력 막대(빨강)·궁극기 막대(파랑, 차면 금색, 궁극기가 없으면 숨김), 쓰러지면 어둡게 "복구".
- StageDeviceButtons·StageDeviceButton: 전투 중 오른쪽 아래(웨이브 시작 자리, 전투 중 "방어 중" 버튼은 숨김)에 수동 장치(밀치기·낙석) 버튼 최대 4칸. 고른 장치는 금색 테두리와 F 표시, 재사용 중이면 남은 초·진행 막대. 버튼을 누르면 그 장치를 고르고 발동을 요청한다. 맵에서 장치를 누르면 그 장치가 F 대상이 되고, 처음에는 첫 수동 장치를 고른다. F로 고른 장치를 발동한다(창이 열려 있으면 받지 않음).
- 배치 고침(2026-11-04, 사용자 "ui가 너무 왼쪽에 모여있어"): 위 띠를 화면 너비로 늘이고 코어·금화는 왼쪽, 웨이브·진행 막대·남은 적은 가운데, 배속·설정은 오른쪽에 둔다. 준비 단계 제목·적 예고와 알림 한 줄은 띠 아래 가운데. 화면 비율이 바뀌어도 세 덩어리가 양끝·가운데에 남는다.
- 리뷰 뒤 정리(2026-11-04): 메뉴 판단은 StageTrapRingController, 전투 패널은 StageBattlePanels가 맡는다. 메뉴가 열린 채 다른 칸을 누르면 닫고, 함정·부하 도구를 들고 있으면 그 클릭으로 바로 놓는다. 위 알림의 세션 안내는 4초만 보인다.
- 확인: 초상(쓰러진 부하 "복구"·체력 막대), 장치 버튼 선택 표시, 버튼 발동 요청(범위에 적이 없다는 안내), 재사용 표시(값을 넣어 화면만 확인). 적이 범위에 있을 때의 실제 발동과 궁극기 막대는 이번 화면에서 보지 못했다.

## 2026-11-03 함정 본편 씬 정리와 HUD 다듬기 (질문 확정, 구현·빌드 확인)

사용자: "씬좀 정리하고 ui좀 수정하자". 질문으로 고른 범위를 모두 적용했다. 생성기 StageHudPolishBuilder(TrapCampaign 생성기 끝에서도 다시 적용)가 씬을 고치며, HUD 새 칸이 비어 있는 원본 StageDefense는 예전 한 줄 표시를 그대로 쓴다.

- 씬: 최상위 15개를 Systems(세션·배속·런타임 에셋·이벤트 시스템) / World(카메라·조명·맵·코어·문·액터·커서) / UI(HUD·설정·팝업) 아래로 묶었다. 편집 중 칠한 문 그림 복제본은 지운다(실행 중 다시 만든다). 함정 본편에서 안 쓰는 HUD 요소는 확인 결과 없어 숨기지 않았다(보급품·상인·부하 명령은 쓰인다).
- 상태 줄: 코어·금화(크게)·웨이브/보스·남은 적·문을 고정 폭 칸으로 나눴다.
- 위 브리핑 줄: 준비 단계 적 예고·결과 상세·튜토리얼, 없으면 규칙·장치 안내.
- 아래: 도구 줄(현재 도구·불가 이유·지형)과 안내 줄(복구 대기 표식·R/E/우클릭 키·색 범례)로 나눴다. 부하 명령 막대는 조금 올렸다.
- 함정 정보 카드: 바닥·벽 함정을 가리키면 커서 옆에 단계·피해·E 강화 비용·철거 환급·R 회전을 보인다. 클릭을 막지 않는다.
- 편성 목록: 바닥 함정 / 벽 함정 / 부하 탭과 작은 줄(62). 벽 함정이 없는 카탈로그는 벽 함정 탭을 숨긴다.
- 지도: 벽 함정 도구로 붙일 수 있는 벽을 가리키면 방향·공격 칸을 미리 보인다. 벽 함정 표식을 종류별 모양(밀치기 겹화살촉·화살·창 세 갈래·독가스 점)으로 구분했다. 구덩이는 바닥과 맞닿은 가장자리에 붉은 테두리를 긋는다.
- 실제 화면 배치·글 잘림은 플레이로 확인하지 않았다.

## 2026-11-03 굽이치는 복도 맵 (질문 확정, 1스테이지 구현)

사용자: "길이 너무 짧아서 그냥 타워 디펜스같아". 질문으로 정했다: 굽이치는 복도 맵, 문→코어 약 2배(약 80칸·50초), 문 수·지형 칸 기믹 종류·적 편성은 유지하고 자리는 복도에 맞춰 새로 잡는다, 1스테이지를 먼저 만들고 확인한 뒤 나머지 6개를 같은 방식으로 만든다.

- 39×15 크기와 벽 띠(위 3줄·아래/옆 1줄)는 그대로 두어 카메라를 바꾸지 않는다. 복도 폭 3칸, 복도 사이 벽 5줄.
- 1스테이지: 문(2,10)→위 복도→오른쪽 꺾임(x 34~36)→아래 복도→코어(2,2). 경로 73칸(이전 39칸). 위 복도 가운데 밀치기 장치(26,10, 아래쪽)와 그 아래 벽을 파낸 구덩이 6칸(x 25~27, y 7~8). 벽이 많아 벽 함정 자리가 늘었다.
- 구현: 에디터 StageCorridorLayout(스테이지별 복도 정의)을 StageTrapCampaignBuilder가 읽어 지형·문·코어·장치·기믹 문구를 바꾼다. 불 구멍·여닫는 문·낙석은 원본 설정을 그대로 두고 자리만 옮긴다. 원본 StageDefense는 바꾸지 않는다.

### 본편 전환 확정 — 후속 구현

사용자 "기획서에 있는거 다해줘", 적용 범위 "본편까지 전환: 자동 함정·수동 장치·위험 지형 중심으로 완성"에 따라 아래 선택으로 본편까지 완성한다. 아래 내용이 기존의 검토/보류 표보다 우선한다.

- 새 게임의 본편 7개 스테이지에 자동 함정·수동 밀치기/낙석·위험 구역 조합을 적용한다. 같은 스테이지 ID·편성 ID·해금·유물·보상·기존 적 편성은 유지한다. 원래 카탈로그/맵은 호환 콘텐츠로 보존하고 새 카탈로그와 맵 복사본을 만든다.
- 기존 준비 체크포인트는 맵 서명이 원래 카탈로그와 일치할 때만 원래 본편으로 복원한다. 그 판은 원래 규칙으로 계속하며 새 게임부터 개편 본편을 쓴다. 일치하지 않는 저장의 보호/오류 처리는 유지하고 파일을 임의로 삭제하지 않는다.
- 바리케이드로 통로를 좁혀 자동 감속/지속 함정을 거치게 하고, 갈림길과 측면 위험 구역에서 수동 장치 발동을 선택한다. 스테이지마다 밀치기 지점과 위험 구역, 후반 낙석/주기 장치를 조합한다. 첫 스테이지부터 속박 수정과 핏빛 웅덩이를 편성할 수 있게 한다. 부하는 선택 가능한 지원 전력으로 유지한다.
- 부하의 일반 스킬과 충전된 궁극기는 교전 중 자동 발동한다. 플레이어의 전투 입력은 수동 장치 클릭에 집중한다. 기존 저장으로 복원된 본편의 수동 궁극기 규칙은 유지한다.
- 밀치기 장치는 준비 단계에 해당 칸을 가리키고 R로 시계 방향 회전한다. 설치/철거는 기존 준비 단계 규칙을 유지한다. 방향은 준비 저장에 포함하고 웨이브 사이에도 유지한다. 기존 저장에 방향 목록이 없으면 맵 기본 방향을 쓴다.
- 밀치기 거리는 일반 적 100%, 방어 역할(Tank) 65%, 보스 35%의 배율을 쓴다(미실측 임시 값, 새 카탈로그 설정). 벽 충돌 피해/즉사는 없다. 무거운 적도 완전 면역으로 만들지 않는다. 기존 본편/실험 카탈로그는 기본 배율 100%를 유지한다.
- 지형 선택은 현재의 지속 피해 구역으로 확정한다. 낙하/즉사는 같은 자리에 중복 구현하지 않는다. 위험 구역은 통행 가능·설치 불가이며 적/아군에게 주기 피해를 준다. 통상 처치 경로로 집계하므로 보상/잔여 적은 한 번만 처리한다.
- 수동 장치의 준비/재사용/대상 없음/이동 차단 이유를 조회와 실행이 공유한다. 개편 본편에서는 빈 낙석도 재사용을 소비하지 않는다. 일시정지/모달 중 입력은 거절한다. 가리킨 장치의 실제 원형 범위·밀치기 경로와 상태를 표시하며 기존 스프라이트를 재사용한다.
- 비용은 재사용 시간만 유지한다. 단축키 일괄 발동·전역 마법·전투 중 구매·지형 파기·부하 삭제·성장 체계 재설계는 이번 기획의 채택안이 아니다. 플레이/테스트/밸런스 실측 금지는 유지하고 구현과 실측 완료를 구분한다.

사용자의 "기획서 기반으로 수정해줘"에 따라 첫 공략 장면을 구현한다. 기존 7개 스테이지와 구 런은 유지하고 별도 TrapLab 씬·카탈로그·맵을 생성한다. 타이틀의 "함정 공략 연습"으로 진입하며 실험 진행·강화·결과는 메모리에서만 관리한다. 정상 판의 체크포인트·프로필·종료 마커를 읽거나 쓰지 않는다.

- 자동 함정은 기존 속박 수정·핏빛 웅덩이 두 종류이며 실험에서는 처음부터 편성한다. 부하는 이번 맵에 제공하지 않아 직접 입력을 장치 발동에 집중한다. 본편 부하·궁극기 규칙은 유지한다.
- 수동 밀치기 장치는 맵에 고정한다. 금색 장치 칸을 클릭하면 반경 안 적을 표시 방향으로 최대 3칸 민다. 비용은 재사용 8초뿐이며 피해는 없다(수치 임시).
- 방향은 상하좌우 한 방향이다. 벽·맵 경계·닫힌 문·바리케이드·살아 있는 부하 앞과 다른 전투원과의 최소 간격에서 멈춘다. 적은 밀린 자리에서 코어로 이동을 다시 계산한다. 기존 스킬의 제한 없는 순간이동은 사용하지 않는다.
- 주황 위험 구역은 설치할 수 없는 통행 가능 칸이며 적·부하에게 0.5초마다 피해 2를 준다(실험에는 부하 없음). 낙하·즉사·무게 저항은 이번 범위에서 제외한다.
- 적이 없거나 아무도 밀 수 없으면 재사용 시간을 소비하지 않고 이유를 알린다. 일시정지·모달 중 입력은 거절한다. 자동 함정은 기존 접촉 발동을 유지한다.
- 장치는 기존 지도 표식 스프라이트를 재사용해 방향 화살표·범위·재사용 상태를 표시한다. 새 외부 그림은 만들거나 수정하지 않는다. 기존 낙석의 발동 동작은 별도로 유지한다.
- 실험은 3웨이브의 일반 적과 무거운 적으로 구성하며 맵·인원·금화는 임시 값이다. 실패/클리어 후 다시 편성할 수 있고 실험 보상은 본편에 반영하지 않는다.

이하의 첫 구현 제안/미정 목록은 이번 선택 이외의 후속 후보로 남긴다. 코드 빌드·편집 모드 재컴파일·에셋 배선 확인까지 수행하며 테스트·플레이·재미/밸런스 실측은 실행하지 않는다.

## 사용자 확정

- 직접 조종하는 캐릭터는 없다. 플레이어의 전투 중 직접 조작은 함정·장치 발동이다.
- 기본 함정은 자동, 강력한 함정·장치는 수동인 혼합 방식이다. 모든 함정을 클릭해 작동시키는 방식으로 바꾸지 않는다.
- 동선 설계와 함정 배치, 적이 들어왔을 때의 발동 타이밍을 중심 플레이로 삼는다.
- 부하 자동 교전 중심의 현재 체감에서 함정과 지형의 활용이 더 큰 역할을 하는 방향으로 전환한다. 부하 삭제나 배치 한도·성장 규칙 변경까지 확정한 것은 아니다.

## 목표로 하는 한 장면

아래는 구현 제안이며, 함정 종류·지형·보상 규칙은 아직 확정하지 않았다.

1. 바리케이드로 적을 함정이 이어진 통로에 유도한다.
2. 자동 감속 함정이 선두를 늦춰 적 무리가 모인다.
3. 플레이어가 적이 모인 시점에 수동 밀치기 함정 또는 범위 장치를 발동한다.
4. 적이 위험 지형이나 다른 함정으로 이동해 추가 피해를 받는다.
5. 빠져나온 적과 다음 무리를 보고 다음 발동을 준비한다.

같은 금화·같은 함정을 써도 배치 방향과 발동 시점에 따라 결과가 달라져야 한다. 피해량·영구 강화만으로 이 장면의 차이를 대신하지 않는다.

## 첫 구현 제안 — 공략 장면 하나

전체 스테이지·유물·보상 체계를 한꺼번에 바꾸지 않는다. 기존 7개 스테이지와 사용자 저장을 보존하는 별도 실험 맵 또는 별도 진입 경로를 먼저 제안한다. 새 씬/맵 여부와 구체 수정 범위는 구현 전 승인받는다.

- 자동 함정 2종: 감속으로 적을 모으는 역할, 모인 적에게 피해를 주는 역할. 기존 속박 수정·지속 피해 함정 재사용을 우선 검토한다.
- 수동 함정/장치 1종: 기존 낙석으로 발동 조작을 재사용하거나, 위치 변화를 검증할 밀치기 함정을 제작하는 두 안을 비교한다. 목표 장면을 입증하는 안은 밀치기이며, 사용 가능한 그림과 구현 범위를 먼저 확인한다.
- 지형 상호작용 1종: 위험 구역 또는 낙하 구역 중 하나만 검토한다. 바닥이 아닌 낙하 칸을 도입하면 현재 IsFloor/A*와 도달·처치·보상 계약을 함께 정의해야 한다.
- 적은 기존 일반 적과 무거운 적 등 소수만 재사용한다. 무게별 밀치기·저항 규칙은 아직 확정하지 않는다.
- 수동 발동은 지도에서 해당 함정·장치를 선택하는 방식을 기준안으로 둔다. 단축키·묶음 발동·전역 마법은 이번 확정에 포함하지 않는다.

## 안전한 구현 경계

- 구매·배치·철거 준비 단계 제한, 스테이지 진행·패배·해금·저장은 별도 변경 승인 전까지 유지한다. 이번 방향 확정이 전투 중 구매/배치 허가를 뜻하지 않는다.
- 강제 이동과 자발적 이동은 분리해 설계한다. 부하의 자발적 추적 반경을 그대로 적용해 모든 밀치기를 거절하거나, 제한 없이 위치를 덮어쓰는 방식을 채택하지 않는다.
- 강제 이동으로 벽/맵 밖에 고립된 적이 생기지 않아야 한다. 낙하를 도입하면 유효한 낙하 종료와 잘못된 좌표 이탈을 구분한다.
- 처치·낙하·코어 도달·중단의 보상/잔여 적 집계는 각각 한 번만 처리한다.
- 수동 발동의 가능 여부·잠금 사유·범위·재사용 상태는 화면 안내와 실제 실행에서 같은 규칙을 사용한다.
- 기존 외부 에셋·씬/프리팹 YAML을 직접 수정하지 않는다. 함정 그림은 기존 팩에서 사용 가능한 자산을 먼저 확인한다.
- 테스트·플레이·밸런스 실측 금지는 유지한다. 향후 실측이 허용되기 전에는 재미·난이도·입력 가독성을 검증했다고 기록하지 않는다.
