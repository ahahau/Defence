# 스테이지 정예 투입

2026-11-01 사용자 결정으로 정예 4종(방패병·궁수·척후병·치유사)을 스테이지 웨이브에 넣는다. 정예 데이터·그림·아우라는 구 일차 경로에서 만든 것을 그대로 쓰고 능력치는 바꾸지 않는다.

## 확정 규칙

- **자리:** Stage_03부터 보스 직전 웨이브에만 넣는다. 일반 적 한 자리를 바꾸므로 웨이브 길이는 그대로다. 첫 파티는 일반 적으로 두고 둘째 파티부터 하나씩 넣는다. 방패병·척후병(전열)은 파티 맨 앞, 궁수·치유사(후열·지원)는 맨 뒤 자리다. 표식 적 자리(파티 둘째)와 겹치지 않아 정예는 파티와 함께 걷는다.
- **종류:** 스테이지마다 고정이다. 배치는 임시다.

| 스테이지 | 웨이브 | 정예 |
|---|---|---|
| Stage_03 | 3/4 | 방패병 |
| Stage_04 | 4/5 | 궁수 |
| Stage_05 | 4/5 | 척후병 |
| Stage_06 | 5/6 | 치유사 + 방패병 |
| Stage_07 | 5/6 | 궁수 + 척후병 |

- **정예 판정:** 카탈로그의 정예 목록(`StageCatalogSO.Elites`)만 정예로 본다. 등급만 보면 일반 검사·성기사도 정예와 같은 4라서, 구 경로의 `PauseLockRules`(강함 4 이상) 기준을 쓰면 검사가 나오는 웨이브마다 일시정지가 잠긴다. SampleScene 규칙은 그대로 둔다.
- **일시정지 잠금:** 정예가 살아 있는 동안 멈출 수 없다. 보스가 살아 있으면 보스 문구, 아니면 `PauseLockRules.EliteLockReason`을 쓴다.
- **안내:** 입장하면 "정예 방패병 등장"(데이터 이름에 "정예"가 들어 있다), 상태 줄의 웨이브 뒤에 "· 정예 N"(준비·전투 모두).
- 코어 도달 피해는 정예 데이터의 기본값 1이다(검사는 2). 밸런스 작업 전이라 정예 에셋은 건드리지 않았다.

## 구현

| 위치 | 역할 |
|---|---|
| `StageCatalogSO.Elites`·`IsElite` | 스테이지 정예 목록 |
| `StageWave.EliteCount(catalog)` | 보스를 뺀 웨이브의 정예 수(준비 예고) |
| `StageSession` | 매 프레임 보스·정예 생존으로 `SetPauseLock`. 정예 입장 안내 |
| `StageHudView` | 상태 줄 "· 정예 N" |
| `StageDefenseBuilder.EliteTable`·`ApplyElites`·`PlaceElites` | 표대로 이미 쓴 스테이지의 자리를 바꾸고 카탈로그 목록을 쓴다. 같은 자리에 다시 써서 여러 번 돌려도 같다. 모든 스테이지의 자리를 먼저 검사하고, 웨이브 밖이거나 표식 적 자리가 하나라도 있으면 아무것도 바꾸지 않고 멈춘다. `BuildStageSet`도 같은 함수를 부른다 |

저장 형식·경로 미리보기·파티 묶음·정예 능력치·아우라는 바꾸지 않았다.

## 커밋 의존

정예 4종의 데이터(`Assets/07.SO/Enemies/Elite*Enemy.asset`)·애니메이션·그림 폴더는 다른 세션이 아직 커밋하지 않은 파일이다. 이 작업을 커밋하려면 함께 넣어야 한다. 아우라(`EnemyEliteAura`·셰이더·재질·`Enemy.cs` 연결)는 없어도 동작한다.

## 검증 한계

Runtime/Editor 빌드·Unity 재컴파일 오류 0, `ApplyElites` 실행 후 스테이지 7개 검증 통과·정예 7자리(표와 같음, 표식 없음)·카탈로그 정예 4종을 편집 모드에서 확인했다. 테스트·플레이는 하지 않았다. 정예가 파티 안에서 실제로 앞·뒤에 서는지, 잠금 문구와 등장 안내가 겹쳐 읽히는지, 체감 난이도는 미검증이다.
