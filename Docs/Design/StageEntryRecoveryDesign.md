# 스테이지 편집 실행과 저장 복원 안내

2026-10-29 사용자 승인: 스테이지 편집 중 두 게임 씬의 동시 실행을 방지하고, 저장 검증 실패 원인을 구체적으로 안내한다. 테스트·플레이 조작은 실행하지 않는다.

## 원인과 범위

SampleScene과 StageDefense에는 GameSpeedController가 각각 하나 있다. 미저장 작업을 보존하려고 두 씬을 Additive로 열어 둔 편집 상태에서 기본 Play를 사용하면 두 게임 흐름이 동시에 시작될 수 있다. 런타임의 중복 검사·일시정지/배속 규칙은 유지한다.

기존 Stage_01 저장의 맵 호환 서명은 현재 39×15 홀의 서명과 다르다. 복원 거절은 보호 동작이며, 검증을 우회하거나 저장을 새 지형에 자동 변환하지 않는다.

## 편집기 실행 경로

- Editor 전용 StageEditorPlayEntry가 씬 열기/닫기·활성 씬 변경·편집 모드 복귀에 반응한다. StageDefense가 열려 있고 별도 시작 씬이 없으면 EditorSceneManager.playModeStartScene을 StageDefense로 지정한다.
- 현재 편집 중인 씬을 직접 저장/닫기/재생성하지 않는다. 시작 씬 로딩과 편집 상태 복귀, 미저장 처리 안내는 Unity 표준 절차를 사용한다.
- 이 도구가 지정한 시작 씬만 StageDefense가 닫힐 때 해제한다. 외부에서 이미 지정한 시작 씬은 덮어쓰지 않는다. 소유 여부는 Editor SessionState에만 보관하고 새 런타임 정적 가변 상태/싱글턴은 만들지 않는다.
- 플레이/전환/컴파일 중에는 시작 씬 설정을 변경하지 않는다. 이번 작업에서는 Play/Stop을 호출하거나 재생 콜백을 모의 실행하지 않는다.
- 공식 API: [EditorSceneManager.playModeStartScene](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityeditor/scenemanagement/editorscenemanager/playmodestartscene). 실제 편집 상태 복귀와 미저장 변경 보존의 재생 실측은 미검증으로 남긴다.

## 저장 실패 안내

기존 HUD 안내 영역을 그대로 사용한다. 새 화면·버튼·자동 새 게임을 추가하지 않는다.

```text
이어하기 불가: 맵·설정이 변경됐습니다.
타이틀에서 새 게임을 선택하세요.
기존 저장·백업을 보호합니다.
```

StageCheckpoint.Validate가 원인을 반환한다. 버전/필수 목록·자원/편성 한도·스테이지 ID/해금·현재 설정·맵 호환 서명·웨이브/잠금/코어·마지막 결과·편성 종류·배치/강화·유닛·바리케이드·함정 상태/면적을 구분한다. 복원은 검증 실패 원인과 새 게임 안내를 표시하고, 현재 상태의 저장이 실패할 때도 구체 원인을 남긴다. 검증 순서/범위와 실패 시 자동 저장 차단·백업 보호·종료 마커·초회 보상/영구 강화 계약은 유지한다.

새 게임은 사용자가 기존 타이틀 버튼에서 명시적으로 선택할 때만 기존 종료 마커/보관 절차를 따른다. 구현/확인 과정에서 사용자 저장·백업·프로필 파일을 쓰거나 삭제하지 않는다.

파일 파싱/버전 검사를 통과하지 못한 경우에는 기존 StageCheckpointStore의 원본/백업 읽기 안내를 유지한다. 이번 원인별 안내는 형식 읽기를 통과한 뒤의 의미 검증에 적용한다.

## 검증 범위

Runtime/Editor 빌드와 가능한 편집 모드의 Unity 재컴파일/콘솔 조회만 수행한다. 테스트 러너·Play/Stop·씬 전환/입력/저장 왕복·밸런스 실측은 수행하지 않는다. 실제 동시 실행 방지·미저장 편집 복귀는 코드 작성과 빌드 확인을 넘어 검증했다고 주장하지 않는다.

## 반영 결과

StageEditorPlayEntry는 편집기 이벤트 등록/재컴파일 전 해제를 짝지었다. 스테이지가 닫히거나 편집기가 정상 종료될 때 이 도구가 지정한 시작 씬만 해제한다. 다른 도구/사용자의 시작 씬은 덮어쓰지 않는다. 씬 저장/닫기/Play/Stop을 호출하는 코드는 넣지 않았다. StageCheckpoint는 의미 검증의 각 실패에서 이유를 반환하고, 복원과 저장 실패에 이 이유를 전달한다. 게임 수치/실행 중 배속 관리자/서명/저장 형식은 유지했다.

Runtime 빌드 15경고/0오류, 새 편집기 소스를 포함한 Editor 빌드(의존 프로젝트 포함) 55경고/0오류. 편집기 상태가 계속 playing이어서 Unity 재컴파일·프로젝트 재생성·실행은 요청하지 않았다. 기존 csproj를 편집하지 않고 임시 MSBuild 소스 추가 타깃을 Assembly-CSharp-Editor로 한정해 빌드했다. 실제 컴파일러 입력과 산출물 메타데이터에서 새 타입은 Editor에만 있고 Runtime/GameLib에는 없음을 확인했다. 이 확인은 Unity 통합 컴파일 통과를 의미하지 않는다.

마지막 읽기 조회(2026-10-29 10:36 KST)에서 콘솔 groundTruth 오류 1개였고, 10:22의 StageHudView.OnEnable ArgumentException 기록이다. 이번 수정 전 발생 기록이며, HUD 재활성화 흐름의 별도 점검 대상으로 남긴다. 콘솔은 지우지 않았다. 기존 배속 중복과 저장 검증 거부의 재현/해소 여부도 플레이 금지로 확인하지 않았다. 근거·작업 전 백업·작업 차이: tmp/stage-entry-recovery-20261029.
