# 함정 추가: 수정 셋 + 번개 구름

2026-10-27 사용자 요청: 함정부터 늘린다. 쓸 수 있는 그림을 확인한 뒤 1안(수정 셋)과 2안(번개 구름)을 묶어 기획한다. **상태: 구현됨(2026-10-27 사용자 승인, 정할 점 셋은 추천대로).** 수치는 기존 함정 기준의 초기값이고 밸런스는 아직 보지 않는다. 결과는 맨 아래.

## 왜

- 함정이 3종(불 화로·핏빛 웅덩이·마력 수정)뿐이다. 경영의 축이 공간인데, 방을 경비로 쓸 때 고를 것이 벌이 시설(10종)보다 훨씬 적다.
- 규칙(`building-rules.md`, 2026-10-21 사용자 결정): 함정은 팩에 애니메이션 그림이 있는 것만 둔다.

## 쓸 그림 (직접 열어 확인함)

| 함정 | 몸체(반복) | 발동 연출(한 번) |
|---|---|---|
| 속박 수정 | `Objects/FG_Crystal_Green_1.png` 8프레임 16×16 | 마력 수정과 같은 계열 터짐(`plash explore/green`) |
| 충격 수정 | `Objects/FG_Crystal_Red_1.png` 8프레임 16×16 | 불꽃 계열(`plash attack/orange`) |
| 노출 수정 | `Objects/FG_Crystal_Gold_1.png` 8프레임 16×16 | 금빛 기둥(`effect2_golden`) |
| 번개 구름 | `Effects/MagicSpell6/StormSpell.png`의 구름 3프레임(줄0 칸4·줄1 칸0·줄1 칸5, 구름 약 56×35) | 같은 시트의 번개 프레임(줄0 칸5~9, 줄1 칸1~4. 한 칸 96×160, 번개 길이 약 4.5칸) |

- 수정 셋은 지금 마력 수정과 같은 시트 모양이라 지금 생성기(`TrapBodyBuilder`)에 그대로 들어간다.
- `StormSpell`은 지금 아무 데서도 쓰지 않는다. 몸체는 구름만 남은 프레임 셋을 오가게 하고, 번개는 발동 때 기존 `TrapTriggerVisual.PlayOnce`로 한 번 재생한다. 구름이 흩어지는 프레임(줄1 칸6~9)은 몸체가 남아 있는데 구름이 사라지는 것처럼 보여 쓰지 않는다.
- 제외: 붉은 웅덩이·주황 화로는 지금 함정과 모양도 역할도 같다. 문(48×32)은 칸 크기와 맞지 않는다. 해골 화살은 쏘는 장치 그림이 없다.

## 상태이상을 실제 값으로 다시 본 결과

이 게임의 상태이상은 이동을 막거나 방어를 깎지 않는다. 바꾸는 것은 **공격 간격 배율**과 **함정에게 받는 피해 배율**, 그리고 지속(지나는 방 수)뿐이다. 그래서 앞서 말한 "갑옷 파괴로 방어를 깎는다"는 실제와 달라, 금빛 수정은 노출로 바꾼다.

| 상태이상(기존 에셋) | 공격 간격 | 함정 피해 | 지속 | 지금 쓰는 함정 |
|---|---|---|---|---|
| 화상 | ×1.15 | ×1.2 | 2방 | 불 화로 |
| 출혈 | — | ×1.4 | 2방 | 핏빛 웅덩이 |
| 취약 | ×1.2 | ×1.2 | 2방 | 마력 수정 |
| 속박 | ×1.15 | — | 2방 | (새) 속박 수정 |
| 기절 | ×1.6 | — | 1방 | (새) 충격 수정 |
| 노출 | ×1.2 | ×1.5 | 1방 | (새) 노출 수정 |
| 방어 파괴 | — | ×1.2 | 2방 | 안 씀 — 출혈·취약과 겹침 |

새 상태이상은 만들지 않는다. 같은 에셋을 스킬도 쓰고 있으면 설명 문구가 공유된다.

## 함정 넷

| | 속박 수정 | 충격 수정 | 노출 수정 | 번개 구름 |
|---|---|---|---|---|
| 역할 | 싸게 무리 전체의 손을 늦춤 | 한 명(탱커·보스 호위)을 크게 늦춤 | 짧게 함정 피해를 크게 키움 — 다음 방 웅덩이·구름과 엮음 | 비싸고 느리지만 넓게 큰 피해 |
| 방식 | 범위(반경 1칸, 아군 포함) | 밟기 | 범위(반경 1칸, 아군 포함) | 범위(반경 1칸, 아군 포함) |
| 칸 | 1×1 | 1×1 | 1×1 | 2×2 |
| 상태이상 | 속박 | 기절 | 노출 | 없음(피해만) |
| 설치비 | 30G | 35G | 50G | 90G |
| 피해 / 일차당 증가 | 5 / 0.35 | 8 / 0.45 | 6 / 0.4 | 24 / 0.9 |
| 재사용(게임 초) | 6 | 7 | 8 | 12 |
| 위험도·등급 무게 | 2 | 2 | 3 | 4 |
| 해금 | 3일차 | 9일차 | 15일차 | 20일차 |

- 기존 함정 셋은 1·6·12일차라 새 넷을 사이사이에 둔다(3·9·15·20). 메타 진행도 조건은 걸지 않는다(필요하면 번개 구름만 진행도 10으로).
- 발동 확률은 모든 함정 공통 0.6(`TrapBodyBuilder.TriggerChance`), 부상(상태이상) 확률은 기존처럼 1.
- 범위형 셋은 아군도 맞는다(설치 카드에 "아군 포함"이 자동으로 나간다). 부하와 같은 방에 둘지는 플레이어가 고른다.
- 공병은 모든 함정을 해체한다. 비싼 번개 구름의 약점이다.
- 함정 지대 방 특수 효과(+50%)·대장간 강화 등은 기존 `Trap.CurrentDamage` 경로를 그대로 탄다.
- 위 수치는 구현 승인용 초기값이다. 실제 밸런스는 나중에 실측한다.

## 만드는 방법

전부 기존 생성기를 늘려서 만든다. 새 런타임 클래스·저장 형식·씬 YAML 직접 편집은 없다.

1. **`TrapBodyBuilder`**
   - `Specs`에 넷을 추가한다. 수정 셋은 기존 마력 수정과 같은 형식이다.
   - 번개 구름은 한 줄에 이어진 프레임이 아니라 시트 여기저기의 칸을 쓰므로, `Spec`에 "쓸 칸 목록"(줄·칸 쌍)을 받는 선택 필드를 더한다. 비어 있으면 지금처럼 한 줄을 읽는다(기존 셋 결과는 바뀌지 않아야 한다).
   - 번개 구름 몸체 칸은 2×2(64픽셀)라 구름(약 56×35)이 들어간다. 텍셀 크기 규칙(칸 32픽셀)은 그대로다.
2. **`TrapEffectBuilder`**
   - 수정 셋은 기존 효과 폴더(낱장 프레임)를 연결한다.
   - 번개 구름은 시트를 잘라 낱장 프레임(`Assets/04.Sprites/Tilesets/Generated/TrapFx_StormCloud_<n>.png`)으로 만든 뒤 같은 방식으로 연결한다. 번개 아래 끝이 함정 칸에 닿게 아래 맞춤(`bottom = true`)으로 둔다.
   - `PlayOnce`는 범위 폭(2×2 + 반경 1 → 4칸)에 맞춰 그림을 늘린다. 번개 연출은 텍셀이 약 1.3배 커진다. 이미 다른 발동 연출도 같은 방식이다.
3. **등록**(Unity CLI 에디터 스크립트): `DungeonUnlockCatalog`에 해금일과 함께, 씬 `NodePanelView.installableBuildings`에 넷을 넣는다.
4. **규칙·테스트**
   - `TrapTileTests.TrapRoster_IsOnlyTrapsWithPackArt`의 함정 목록을 7종으로 고친다(해금 목록과 같아야 한다는 검사는 그대로).
   - `TrapData_BoardSpriteMatchesPrefabBodyAndIsUnique`가 새 넷의 그림 중복을 잡는다(수정 셋은 색이 달라 다른 그림).
   - 새 테스트: 번개 구름처럼 칸 목록으로 자른 함정도 몸체 프레임이 비지 않고 발동 연출 프레임이 연결됐는지.
   - `building-rules.md`의 "지금 셋" 문구를 7종으로 고친다.
