# 웨이브 방어 결과 요약

2026-10-29 사용자 승인: 기존 화면에서 웨이브 성과·클리어 보상·다음 행동을 표시하고, 마지막 준비 단계 결과도 이어하기에 보존한다. 테스트·플레이·밸런스 실측은 실행하지 않는다.

## 표시와 목업

기존 왼쪽 안내 영역(374×142, 기본 18pt)을 사용한다. 결과가 있는 동안만 14~18pt 자동 맞춤으로 영역 크기를 유지하고 일반 안내는 원래 글자 크기로 복구한다. 석판/금빛 테두리·기존 TMP/색을 유지하고 새 버튼이나 중앙 팝업을 추가하지 않는다. 다음 웨이브 번호를 보여 주는 상단 진행 상태와 방금 종료한 웨이브의 결과 번호를 구분한다.

```text
1웨이브 방어 완료
처치 8 · 도달 2
코어 피해 10
금화 +85G (파괴 환급 포함)
다음 웨이브를 준비하세요

[기존 웨이브 시작 / 스테이지 재도전 버튼]
```

실제 완료/실패 시점의 처치·도달·실제 코어 손실·획득 금화를 확정한다. 실패한 웨이브는 미출현/살아 있는 적을 처치나 도달로 세지 않는다. 전투 중 획득 금화는 처치 보상과 바리케이드 파괴 환급을 포함하며 준비 중 철거 환급·구매는 포함하지 않는다. 금화 표시에 환급 포함을 밝힌다. 전투 중에는 결과를 숨기고 기존 피격 안내를 사용한다. 저장 오류는 결과보다 먼저 표시한다.

클리어 강화 재화는 금화와 별도 행으로 표시한다. 기존 Profile.TryClear 성공의 실제 지급액만 읽고, 재표시/보상 저장 재시도로 추가 지급하지 않는다. 이미 초회 보상을 받은 스테이지는 이번 지급 0으로 구분한다. 저장 실패는 미확정 상태로 표시하고 기존 보상 저장 재시도 버튼을 유지한다. 다음 행동은 기존 시작/다음 스테이지/재도전 버튼과 도구 안내를 사용한다.

## 클리어 요약 후속 (2026-11-02)

사용자 승인: 결과 정보 밀도 문서의 후속(스테이지 누계·보스 성과·이번 해금 목록)을 클리어 요약에 넣는다. 같은 안내 영역·크기·버튼을 쓰고 패배 요약은 그대로다.

```text
스테이지 클리어 · 6웨이브 방어
누계 처치 58 · 도달 4 · 코어 피해 9
보스 정복자 처치            (도달했으면 "코어 도달")
강화 재화 +3 (초회)
해금 슬롯 +1 · 충격 수정, 핏빛 웅덩이   (이름은 둘까지, 넘으면 "외 N")
다음 스테이지를 준비하세요   (안내 문구: 강화·유물 조작 결과도 이 줄)
```

- 리뷰 보완(2026-11-02): 처음에는 다음 행동이 도구 줄에 있어 안내 문구를 뺐으나, 클리어 뒤에도 영구 강화·유물 고르기가 가능해 그 결과 문구가 보이지 않았다. "이번 웨이브" 줄을 빼고 안내 줄을 항상 남겨 6줄을 유지한다. 누계가 없는 판만 누계 자리에 마지막 웨이브 전과를 보인다. 해금 줄은 374px 한 줄에 들도록 슬롯 보상을 앞에 짧게 쓰고 이름을 둘까지만 적는다.
- 금고 보수 같은 코어 회복이 생기면 누계/마지막 요약 검사의 "코어 피해 ≤ 실제 손실" 조건(`MatchesTotals`·`MatchesPreparation`)이 회복한 판을 복원 실패로 막는다. 회복 기능을 넣을 때 두 검사를 함께 고친다.
- 누계(`StageWaveResults.Totals`)는 웨이브가 끝날 때마다 더하고 스테이지 시작·재도전에서 0으로 돌린다. 준비 저장에 선택 항목 `hasStageTotals`/`stageTotals`(같은 `StageWaveReport` 형식)를 추가했다. 끝난 웨이브 수·처치+도달 = 지난 웨이브 인원 합·코어 피해 ≤ 실제 손실·마지막 요약 이상을 검사하고 어긋나면 기존 복원 실패 경로로 막는다. 필드 없는 구 저장은 첫 웨이브 전이면 0에서, 아니면 누계를 모르는 채로 복원해 누계 줄을 숨긴다.
- 보스 성과는 마지막 웨이브에서 보스가 처치됐는지/코어에 도달했는지(`BossDefeated`·`BossArrived`)다. 전투 중 종료는 준비로 돌아가므로 저장하지 않는다.
- 해금 줄은 초회 지급이 확정된 클리어에만, 이 스테이지 클리어가 조건인 편성 종류(`StageOption.RequiredClear`)와 슬롯 보상 스테이지의 "편성 슬롯 +1"을 카탈로그에서 계산한다. 없으면 숨긴다. 다음 스테이지 개방은 도구 줄 안내가 맡는다.
- 확인: Runtime/Editor 빌드·Unity 재컴파일 오류 0, 콘솔 오류 0. 테스트·플레이·저장 왕복을 하지 않아 실제 글 넘침·이어하기 누계는 미검증이다.

## 책임과 저장

- StageWaveResults: 전투 집계·확정 결과·이번 클리어 지급 확정 상태. StageSession은 시작/적 퇴장/전투 환급/종료 경계만 전달한다.
- StageWaveReport: 직렬화 가능한 읽기 전용 확정 결과. UI는 결과를 읽고 보상을 지급하지 않는다.
- StageWaveResultPresenter: 기존 안내 문구와 결과·보상·후속 행동 표시. 화면은 렌더링만 연결한다.
- StageCheckpointData에 선택 항목 hasWaveReport/waveReport를 추가한다. 기존 v1 필수 계약/서명/버전은 유지하고, 명시적 존재 플래그가 없는 구 저장은 결과를 생략한다. 버전이 다른 구 런 파일은 건드리지 않는다.
- 요약이 존재하면 완료된 직전 웨이브 번호·완료 여부·처치+도달 합계·음수 금화/피해·현재 코어 체력과 피해의 정합성을 검사한다. 잘못된 결과는 기존 복원 실패/저장 차단 경로로 처리해 원본/백업을 보호한다.
- 준비 단계 체크포인트에만 마지막 완료 결과를 넣는다. 전투 중 종료는 마지막 준비로 돌아가며 미완료 전투 통계를 저장하지 않는다. 클리어/패배는 기존 종료 마커 계약을 유지하고 종료 결과를 이어하기로 복구하지 않는다.

보상·금화·코어·웨이브 수치와 기존 복구/자동 저장 시점은 유지한다. 씬/프리팹/YAML과 실제 사용자 저장 파일은 수정하지 않는다. 구현 후 Runtime/Editor 빌드·Unity 재컴파일·콘솔 오류만 확인하고 화면 배치·전투·저장 왕복 실측은 미검증으로 기록한다.

## 반영 결과와 확인 한계

3개 C# 파일로 결과/집계/표시 책임을 분리하고 기존 세션·HUD·체크포인트에 연결했다. 0 재화로 설정된 첫 클리어도 이전 수령과 구분하고, 보상 저장 재시도/강화 조작 뒤에도 이번 실제 지급액을 유지한다. 기존 시작/다음 스테이지/재도전 버튼을 그대로 사용한다.

최종 Runtime 빌드 15경고/0오류, Editor 빌드 0경고/0오류. 결과 요약의 Unity 재컴파일은 완료/오류 없음이다. 콘솔에서 StagePlacementTool.Hide의 파괴된 SpriteRenderer 접근 예외를 발견해 null 검사를 추가했고 이 보완까지 두 빌드가 통과했다. 마지막 Unity 재컴파일 요청은 HTTP 400으로 거부됐으며 읽기 조회에서 편집기가 playing이었다. 강제로 중단/재시작하거나 추가 실측하지 않아 마지막 커서 보완의 Unity 최종 재검증은 미확인이다.

콘솔 오류 0을 주장하지 않는다. 배속 관리자 중복·스테이지 저장 검증 실패·보완 전 커서 예외 기록(groundTruth 3개)이 남아 있고 지우지 않았다. 실제 저장을 읽기만 해 version=1/Stage_01/nextWave=0/hasWaveReport 필드 없음까지 확인했으며 새 요약 검증은 존재 플래그가 true일 때만 실행된다. 기존 저장의 다른 검증 실패 원인은 후속 점검 대상이다. 사용자 파일을 삭제/변환/저장하지 않았다.

에이전트는 테스트 러너·Play/Stop·모의 입력/전투·밸런스 실측을 실행하지 않았다. 정적 씬 조회 때는 SampleScene만 열려 있어 실제 결과 화면 캡처/가독성·저장 왕복도 확인하지 않았다. 근거·작업 전 백업·이번 작업 차이는 tmp/stage-wave-results-20261029에 남긴다.
