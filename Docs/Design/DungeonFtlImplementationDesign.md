# 던전 FTL 구현 설계

2026-11-05 사용자 답(구현 질문 12문 + 후속 6문)을 정리한 문서다. 게임 규칙은 [던전 FTL 전환 기획](DungeonFtlDesign.md)을 따른다.
빈 곳은 추론으로 채우지 않는다. 아래 "미정"에 남기고, 해당 작업 전에 사용자에게 묻는다.

- **현재 상태:** 1층 십자 전투와 배치·위기 화면에 수동 함정·전투 중 마력 고정을 반영했다. 최종 테스트·플레이는 사용자 요청으로 보류 중이다. 아래의 턴제·옆 단면·사다리 설명은 변경 이력이며 최신 확정과 진행 기록을 우선한다.
- **승인:** 코드 작업은 단계마다 범위를 설명하고 승인받은 뒤 시작한다.
- **1층 자리 변경(2026-11-09 사용자 채택):** `RunEncounter_Stage1`의 북 방(행 0)이 함정 방, 가운데 방(행 1)이 문 제어실이 됐다. 아래의 "북 문 제어실·가운데 함정 방"은 그전 기록이다. 문은 두 방 사이 북 복도에 그대로 있었고, 코드는 방 종류로 함정 방을 찾으므로 바꾸지 않았다. 바뀜(2026-11-10 사용자 결정): 문 제어실은 이제 심장으로 이어진 복도(가운데↔심장)의 문을 잠근다(`RunBattle` 생성자). 비교용 켜기 값 `RunBattleSettings.TrapReachesLinks`·`BlocksRepairOfBrokenRooms`는 저장하지 않으며 기본은 꺼져 있다.

## 0. 현재 규칙 요약 (2026-11-09 기준)

아래 절들은 턴제·옆 단면·격자 시절 기록이 섞여 있다. 지금 코드와 데이터(`Assets/01.Code/Run/`, `Assets/07.SO/Run/RunEncounter_Stage1.asset`)의 규칙만 여기에 모았다. 수치는 모두 임시다. 어긋나면 기획 문서와 이 요약이 아래 기록보다 우선한다.

**던전과 시간**

| 항목 | 현재 |
|---|---|
| 1층 | 5방 십자 평면도. 북 함정 방, 가운데 문 제어실, 서 치유 샘, 동 금고, 남 심장(2026-11-09 북·가운데를 맞바꿈). 입구는 북 방 위 굴(길이 1) |
| 길이 | 방 3, 네 방향 복도 3(폭 1.2). 잠긴 문은 가운데 방↔심장 복도에 있다(2026-11-10 북 복도에서 옮김) |
| 입장 | 굴 밖 대기 줄에서 0.75초 간격으로 한 명씩 들어온다(2026-11-10 1.5초에서 바뀜) |
| 시간 | 0.05초 단위로 진행한다. Space로 멈추고 1·2로 배속한다. 멈춘 채로 명령할 수 있다 |
| 끝 | 심장 0이면 패배. 모든 적이 쓰러지거나 떠나면 승리. 도적·공병 침입은 120초가 지나면 남은 적이 물러나 승리하고, 정예 침입은 시간 제한이 없다 |

**자원과 방**

| 항목 | 현재 |
|---|---|
| 심장·금고 | 심장 30, 금고 금화 100. 둘 다 고장 나지 않는다 |
| 마력 | 전투 중 용량 3 고정. 처치로 늘지 않는다. 원정에 이기면 정예 침입만 4. 심장에서 이어진 방에만 흐른다 |
| 마력 칸 | 함정 방 2, 치유 샘 1, 문 제어실 1 |
| 함정 방 | 전력이 들어오는 동안 4초 충전, 수동 발동, 방 안 적 전원에게 마력×2(+상인 함정 강화 2) 피해. 다 찬 뒤에도 4초마다 한 단계씩 최대 3단계까지 쌓이고, 피해는 단계만큼 곱해진다(2026-11-10). 멈춤 중에는 예약 |
| 치유 샘 | 1초마다 마력×1 회복 |
| 문 제어실 | 켜져 있으면 문을 잠근다. 문 내구 10, 적 평타로 깎이며 부서지면 그 판 동안 열린다 |
| 방 고장 | 방 시스템 내구 8. 0이면 고장 나 그 너머로 마력이 끊긴다. 부하가 방에 있으면 초당 수리량만큼 고친다. 고장·내구는 다음 판으로 이어진다 |
| 잘 맞는 방 | 부하가 잘 맞는 방에 있으면 그 방 효과 ×1.5(올림) |
| 처치 보상 | 적 하나당 금화 5(2026-11-17 사용자 결정 "G3"으로 10 → 5. 같은 결정으로 던전 정비 방 수리·부하 치료 20 → 30) |

**싸움**

| 항목 | 현재 |
|---|---|
| 거리 | 근접 0.6, 원거리 2.5, 아군 대상 스킬 1.5. 공격 간격 = 6 ÷ 속도(초) |
| 상성 | 물리 → 마법 → 저주 → 물리. 강하면 ×1.5, 약하면 ×0.75, 올림 |
| 붙잡기 | 이동 명령 중이 아닌 부하가 지키는 방은 적이 지나가지 못한다. 길 고르기에서 지키는 방·잠긴 문은 방 2칸 길이만큼 벌점을 받는다 |
| 물러나기 | 체력 30% 미만인 부하는 치유 샘으로 간다(샘이 꺼졌거나 길이 막혔으면 가지 않는다). 30% 미만일 때 플레이어가 이동 명령을 내리면 명령이 우선하고, 30% 이상으로 회복할 때까지 자동으로 물러나지 않는다(2026-11-10) |
| 적 목표 | 도적은 금고(초당 10, 45를 채우면 굴로 도주), 공병은 가장 가까운 켜진 방(방 피해 2배), 나머지는 심장. 심장에 닿은 적은 머물며 공격 간격마다 공격력만큼 치고, 사거리에 부하가 오면 부하와 먼저 싸운다 |
| 예고 끊기 | 폭파·화염구를 예고 중인 시전자가 있는 방으로 보낸 부하는 길의 적을 지나쳐 가서 시전자를 먼저 친다 |
| 자동 멈춤 | 큰 기술 예고 시작, 방 고장, 도적 금고 도착, 적 심장 진입. 부하 체력 30% 미만은 알림만 띄운다 |

## 2. 지금 코드 재사용

| 대상 | 확정 |
|---|---|
| 전투 | **엔티티·스탯까지 다시 쓴다.** GameLib `Entity`·`StatModule`·`HealthModule`, 부하·적 그림, 애니메이션 묶음(`CharacterAnimationSetSO`·`EntityRender`), 연출 그림을 쓴다. 턴제 때는 실시간 부분(행동 트리 `BattleAgent`·이동·공격 게이지 `Combatant`)을 쓰지 않기로 했으나, 2026-11-05 실시간 전환으로 **다시 쓸지 새로 짤지 미정**이다(함정 본편 코드는 위에서 내려다보는 방 기준이라 옆 단면 바닥선 이동에 맞춰야 한다) |
| 스킬·상태이상·유물 SO | **형식은 다시 쓰고 내용은 새로** 만든다(`SkillDataSO`·`StatusEffectDataSO`·`ArtifactDataSO`를 턴제에 맞게 고친다). 고치는 범위는 해당 단계 설계 때 정한다 |
| 부하·적 데이터 | 그림을 쓸 데이터(`UnitDataSO`·`EnemyDataSO`)의 형식을 어떻게 이어 쓸지는 1단계 설계 때 정한다(미정) |
| 글 사건 | **기존 대화 SO**(`DialogueSequenceSO`)를 쓰고, 부하·방 조건 선택지와 새 액션만 더한다 |
| 저장 | **기존 저장 틀**(`RunSaveSystem`·`SaveAgentRegistry`·`ISaveable` 에이전트: 버전 JSON·백업·교체 안전장치)을 쓰고, 새 런용 섹션을 만든다. 파일 이름은 새로 정한다 |
| UI | **지금 장부형 유지.** `UiKit` 생성기·`HudPalette`를 그대로 쓴다 |
| 단면도 그리기 | **에셋을 보고 결정**한다(타일맵 또는 방 프리팹). 그전에는 단순 도형으로 놓는다 |

## 3. 예전 코드·저장 정리

- **기존 코드·씬·에셋**(함정 본편·경영 판·SampleScene): 새 방식으로 한 런을 끝까지 돌릴 수 있게 된 **뒤에 한꺼번에** 지운다.
- **예전 사용자 저장**(함정 본편 프로필·준비 저장, 경영 판 런·메타): 기존 코드를 지울 때 함께 지운다. 지우기 전에 백업하고, 지울 때 다시 확인받는다.

## 4. 작업 순서

**전투 한 칸 먼저** 만든 뒤, 지도·상점·사건을 붙인다.

> **2026-11-05 실시간 전환:** 기획 8장이 속도 순서 턴제에서 실시간 + 일시정지로 바뀌었다. 아래 1단계의 "구현 방식·전투 화면·전투 규칙·화면 개편·임시 수치"는 **턴제 기준 기록**이다. 방·부하·적 구성, 길막기·목표·마력 끊김처럼 시간과 무관한 답은 살리되, 차례·라운드·속도 순서·줄·라운드 진행 버튼에 걸린 답은 실시간 기준으로 다시 정한다(사용자 답 전에는 미정). 이미 만든 턴제 코드(`RunBattle`, 테스트 23개)는 크게 다시 짜야 하며, 범위는 설명하고 승인받은 뒤 정한다.

### 1단계(첫 목표): 1층 침입 방어 한 판

- **방:** 1층 5방(심장·금고·함정 방·치유 샘·문 제어실).
- **부하:** 시연판 4종(해골 방패병·해골 검사·오크 주술사·해골 저격수).
- **적:** 적 파티 하나(검사·궁수·도적·공병).
- **넣는 규칙:**
  - 속도 순서 턴, 라운드 사이 명령, 적 행동 미리보기
  - 마력 용량·연결, 방 고장·수리
  - 함정 방 이펙트, 잠긴 문, 앞·뒤 줄, 전투 끝 판정
- **빼는 것:** 원정·전송 방(다음 단계).
- **수치:** 제가 임시값 표를 만들어 보여 드리고 승인받은 뒤 넣는다. 기획 문서에는 "임시"로 표시한다.

### 1단계 구현 방식(2026-11-05 사용자 답)

| 항목 | 확정 |
|---|---|
| 데이터 | 턴제 전용 **새 SO**(부하·적 공용)에 체력·공격·속도·줄·수리·스킬을 둔다. 지금 `UnitDataSO`·`EnemyDataSO`에서는 이름·애니메이션 묶음만 연결한다. 예전 데이터는 건드리지 않는다(함정 본편이 그대로 돈다) |
| 인물 프리팹 | Entity·스탯·체력·그림 표시만 단 **새 공용 프리팹 하나**. 행동 트리 없음. 데이터로 그림을 바꾼다 |
| 스킬 | `SkillDataSO`에 **쿨(차례)** 필드를 더하고, 효과는 **턴제용 새 효과 조각**(피해·치유·피해 감소)으로 만든다. 이름·설명·아이콘·주문 그림은 그대로 쓴다 |
| 저장 | 1단계에는 **넣지 않는다**. 지도를 붙이는 단계에서 넣는다 |
| 화면 | **목업을 먼저** 만들어 승인받은 뒤 화면 코드를 짠다. 전투 규칙 코드는 목업과 동시에 진행해도 된다 |

- **화면 실측:** 가상 마우스 클릭으로 함정 방 마력 2칸 배정 → 해골 검사 선택 → 치유 샘 이동 명령 → 라운드 진행을 확인했다. `timeScale` 0에서도 재생 중간 좌표가 바뀌었고 함정 방에서 치유 샘에 도착했다. 화면과 좌표 기록은 `tmp/dungeon-run-ui-20261105/`에 있다.

### 그다음 단계

2026-11-06 승인한 [1구역 시연 런](DungeonFtlDemoRunDesign.md)을 타이틀에서 시작해 정산까지 연결했다. `RunDemoRoute`는 진입과 종료를 관리하고, `RunDemoCampaign`은 전투별 편성과 상인·사건·원정 결과를 관리한다.

결과 띠의 **구역 지도** 버튼은 기존 장부형 팝업을 연다. 지도에서 선택 가능한 칸과 그 효과를 보여 주고, 상인·글 사건과 다음 전투 준비로 연결한다. 원정에서는 진지 평면도로 전환하며, 경로 선택으로 첫 이동을 지시한 뒤 부하와 다음 방을 눌러 이동시킨다. 후퇴 명령 후에는 출구까지 실제로 이동한다.

저장은 `defence-dungeon-demo-v1.json`에 시연 전용으로 기록한다. 칸에 진입하거나 결과를 확정할 때 기록하며, 전투 중 종료하면 해당 칸 준비부터 재개한다. 기존 본편의 저장과 메타 기록은 읽거나 쓰지 않는다. 손상된 시연 원본은 보존하고 백업에서 읽은 런은 자동 저장을 중단한다. 타이틀에서 시연 씬을 열 수 있을 때 새 게임과 이어하기를 시연 런에 연결한다.

기존 [연속 침입 3판](DungeonFtlThreeEncounterDesign.md)은 시연 이전의 프로토타입 기록이다. 시연의 개별 편성과 진행에는 시연 런 기획을 적용한다.

- 결과 띠의 다음 침입 준비 버튼은 1·2판 승리에서 표시한다. 심장 체력·금화·부하별 체력·방 내구와 고장 여부를 준비와 전투 시작에 모두 적용한다. 쓰러진 부하는 준비에서 숨기고 배치 대상에서 제외한다. 기존 배치와 마력은 직전 시작 배치를 사용한다. 전투 타이머·예고·함정 충전과 개별 문의 상태는 새 전투 값으로 시작한다. 편집기에서 씬 배선을 저장했고 플레이 검증은 보류했다.
