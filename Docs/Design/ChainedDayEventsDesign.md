# 선택 후속 사건 설계

2026-10-27. 사용자 요청: 유물 조합 다음에 연속 선택 사건을 진행한다. 아래 범위를 승인받아 구현했다.

## 현재 기능과 필요한 확장

RunEventLedger.ChosenKeys는 선택 이력을 저장하지만, 선택한 일차·후속 사건 예약·처리 여부는 없다. DialogueValueTableSO의 bool 분기는 이 예약/저장 기능을 대신하지 않는다. 이전 선택을 추측해서 후속을 띄우지 않고, 앞으로 실제 선택하는 시점에 예약한다.

## 콘텐츠

방금 추가한 사건 중 공구 공동구매와 야간 추가 근무를 각각 한 번의 후속 사건으로 연결한다. 첫 사건의 선택에 따라 다른 후속 대화가 예약되므로 후속 도입 에셋은4개다. 각 후속은 선택지2개와 선택별 짧은 후일담을 갖는다.

| 앞선 선택 | 후속 사건 | 선택 A | 선택 B |
|---|---|---|---|
| 공구 공동구매 참여 | 작업반의 답례 | 답례 물자를 판다: 금화 +35 | 작업반에 돌려준다: 민심 +4 |
| 예비 공구 매각 | 공구를 빌리러 온 작업반 | 공구를 다시 마련한다: 금화 -15, 민심 +6 | 남은 공구를 더 빌려 쓴다: 금화 +35, 민심 -6 |
| 야간 작업 실시 | 밤샘 작업반의 요청 | 휴식 식사를 지원한다: 금화 -15, 민심 +6 | 추가 납품을 받는다: 금화 +35, 민심 -6 |
| 추가 근무 대신 식사 | 다시 모인 식탁 | 부하들이 모은 물자를 받는다: 금화 +35 | 부하들의 몫으로 남긴다: 민심 +4 |

효과는 기존 액션 에셋만 재사용한다. 이야기 속 부하/공구/물자는 유닛 소유·장비를 생성하거나 제거하지 않는다. 독립 후속은 일반 무작위 목록에 넣지 않아 앞선 선택 없이 등장하지 않는다. 본문/후일담은 임프 참모 화자·두 줄 이내로 작성한다.

## 예약과 등장 규칙

- 첫 사건에서 실제 A/B를 선택하면 그 사건의 후속1개를 예약한다. 아무것도 하지 않음은 예약하지 않는다.
- 가장 빠른 허용 일차는 선택 일차+2다. 그 뒤 일반 사건이 허용되는 전환에서 예약된 후속을 일반 무작위 사건보다 먼저 꺼낸다. 정확히2일 뒤 등장하는 것은 아니다.
- 긴급·운영 방침·상황 사건 우선순위와 일반 사건4~6회 휴식, 한 전환에 사건 하나 규칙은 유지한다. 후속도 일반 사건의 한 자리를 사용한다.
- 여러 후속이 기다리면 예정 일차가 빠른 순서, 같으면 예약 순서다.
- 각 첫 사건은 한 판에 한 번만 후속을 만든다. 같은 사건을 다시 만나 다른 선택을 해도 두 이야기가 상충하거나 후속 보상을 반복하지 않는다.
- 후속의 첫 선택에서 효과를 적용할 때 예약을 완료 처리한다. 아무것도 하지 않음도 완료 처리하며 보상은 없다. 후일담에는 효과가 없다. 선택 전 중단된 후속은 예약을 보존해 다음 허용 전환에 다시 시도한다.

## 코드·저장·연결 범위

- DialogueSequenceSO에 선택 인덱스/후속 시퀀스/최소 지연 일차를 가진 후속 정의를 추가한다. 기존 시퀀스는 정의가 없는 기본값으로 유지된다.
- RunEventLedger에 대기 예약과 완료한 후속 식별자를 관리한다. ID는 첫 사건의 에셋 키를 사용하며 선택지 순서 변경에 유의한다.
- DialogueRunner가 실제 선택 시 예약하고 일반 사건 추출 시 준비된 후속을 우선하며, 후속 선택/건너뛰기를 완료 처리한다. 조립 루트의 기존 민심 관리자와 DayManager의 기존 일차를 사용하며 새 전역 접근자는 만들지 않는다.
- SavedPolicyState에 대기 예약/완료 ID를 선택 필드로 추가하고 MoralePolicyManager의 CaptureSaveState/RestoreCheckpoint에 연결한다. 기존 저장의 누락 필드는 빈 목록으로 처리한다. 기존 선택 이력만 보고 과거 후속을 새로 예약하지 않는다. 저장 파일 버전과 다른 섹션은 유지한다.
- Unity Editor API로 후속 에셋4개(각각 후일담2개 포함)를 만들고 첫 사건2개의 후속 정의에 연결한다. 씬 일반 사건 목록은16개로 유지한다.

## 검증과 기록

장시간 자연 영업/밸런스 실측은 하지 않는다. 코드 변경에 필요한 빌드·관련 EditMode 검사만 수행하고, 에셋의 분기/액션과 예약 지연·우선순위·건너뛰기·중복 방지·옛 저장 기본값/예약 복원을 짧게 확인한다. 작업 전 사용자 저장 파일은 건드리지 않으며 실제 플레이가 필요해지면 먼저 백업한다. 모든 변경을 Sequences.md에 기록한다.

## 구현 결과

- DialogueFollowUpDefinition과 SavedDialogueFollowUp을 추가했다. DialogueSequenceSO는 첫 줄 선택 인덱스에 대응하는 후속을 제공한다. RunEventLedger가 예약 순서/최소2일 지연/완료 이력을 관리하고, 기존 SavedPolicyState에 pendingDialogueFollowUps·completedDialogueFollowUps를 추가해 MoralePolicyManager의 캡처/복원에 연결했다. 사용자 승인한 하위 호환 방식으로 기존 파일 버전은 유지하며 누락된 옛 필드는 빈 상태로 읽는다.
- DialogueRunner의 일반 사건 추출에서만 준비된 후속을 우선한다. 기존 전환 판정의 긴급/방침/상황 우선순위와 휴식 계산은 바꾸지 않았다. 선택/건너뛰기에서만 완료되며, 잘못된 선택 인덱스·닫기·중단은 소모하지 않는다. 런타임 에셋 쓰기·새 싱글턴/검색·매 프레임 처리는 추가하지 않았다.
- 후속 에셋은 DayEvent_ToolCooperative_Thanks/Borrow와 DayEvent_NightOvertime_Request/Table의4개다. 각 파일에 선택별 후일담2개를 서브에셋으로 보관한다. 기존 첫 사건2개에는 후속 정의만 연결했고 원래 대사/효과를 유지했다. 씬 파일 해시는 작업 전과 동일하며 일반 사건 목록은16개다.
- 새 회귀9케이스를 기존 RunEventLedgerTests에 추가했다. 예약 지연/순서·복사 격리·중복 방지·옛 저장·실제 선택/건너뛰기·미선택 후속 재시도·민심 캡처/복원을 확인했다. 관련 검사84/84: RunEventLedgerTests24/24, ArtifactShopTests3/3, DialogueSequencePlayerTests5/5, AssetWiringTests52/52.
- Runtime 빌드 오류0(외부 Feel 경고22), Tests 빌드 경고0/오류0, Unity 재컴파일 오류0. 최초 병렬 dotnet 빌드는 공유 DLL 출력이 충돌했으며 순차 실행으로 수정했다. 새 코드 오류는 아니었다.
