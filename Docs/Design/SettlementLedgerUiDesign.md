# 정산표 한 화면 장부 (A안)

2026-10-27 사용자 승인: 목업 A안(한 화면 장부, 탭 3개). 정할 점 세 가지는 추천대로 — "상세 보기" 없앰, 유닛 상점 탭은 늘 열어 둠, 피로 칩은 가장 지친 둘 + "외 N명".

## 왜 바꿨나

- 옛 요약 칸은 1040×740 카드에 "운영 자금 ±N"과 두 줄뿐이라 절반이 비었다.
- 수입·지출이 다른 탭이라 비교하려면 탭을 오가야 했고, 줄은 색 글자 목록이었다.
- 매일 보는 결과와 청산일에 쓰는 계약·상점이 같은 무게의 탭 다섯이었다.

## 구조

| 자리 | 내용 |
|---|---|
| 제목줄 | 왼쪽 "N일차 정산", 오른쪽 "빚 · 청산일까지 N일"(빚이 있으면 경고 색) |
| 탭 | 오늘 정산 / 계약·부채 / 유닛 상점 |
| 위 띠 | 수입 합계 → 지출 합계 → 낮에 이미 반영 → 남은 운영 자금(정산으로 움직인 액수를 바로 뒤에) |
| 왼쪽 560×440 | 수입·지출 한 장부(이름 왼쪽·금액 오른쪽, 칸 안 스크롤) |
| 오른쪽 | 오늘 전과 칩 6자리 고정(빈 자리는 바탕만 끔) |
| 맨 아래 줄 | 해금 개수 한 줄 + "목록"(펼치면 장부·칩 위를 불투명 칸으로 덮음), 오른쪽 "정산 완료" |

## 값

- `SettlementOverviewPresenter`가 보고서·운영 자금·빚·청산까지 남은 날로 `SettlementOverviewViewModel`을 만들고, `SettlementSummaryPane`은 그리기만 한다.
- 목업의 "시작 금화"는 쓰지 않는다. 보고서의 선지출 몫(`DeferredDelta`)에는 금고로 간 돈도 섞여 있어 운영 자금 시작값으로 역산하면 틀릴 수 있다. 그래서 띠는 "낮에 이미 반영"을 따로 보여 준다.
- 칩: 요약 문구가 있는 메모, 위험 메모(요약 없으면 전문), 피로 상위 둘. 넘치면 일반 메모부터 줄이고 "메모 N개 더" 칩으로 알린다. 위험·피로는 남긴다. 요약 문구가 없는 일반 메모는 칩이 되지 않는다.
- 결과 정보량 설계(`ResultInformationDensityDesign.md`)의 정산 "상세 보기"는 이 화면으로 대체됐다. 메모 전문은 위험 메모만 보인다.

## 검증

- EditMode: `SettlementRegressionTests.SettlementOverview_*` 3개(장부·띠 값, 청산일·빚 문구, 칩 자리·위험 유지·피로 상위 둘·칩 순서 전체), `AssetWiringTests.SettlementOverview_DrawsLedgerChipsAndFoldsUnlocksForEachReport`(프리팹 배선·칩 빈자리·목록 접힘).
- 칩 순서: 일반 메모 → 피로 → "메모 N개 더" → 위험.
- 생성기는 SampleScene 인스턴스를 다시 놓고, 같은 배선 안에서 ESC 라우터도 다시 잇는다(`SettingsBuilder.WireEscapeRouter`, `SettingsScreen_IsPlacedAndEveryWindowClosesWithEscape`가 잡는다).
- 1280×720 실측(4일차): 띠·장부·칩(위험 칩 빨간 바탕)·목록 펼침·다른 두 탭. 긴 장부 스크롤, 정산 화면 고용 뒤 남은 자금 갱신, 1920×1080은 아직 실측하지 않았다.
