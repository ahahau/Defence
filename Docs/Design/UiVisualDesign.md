# UI 시각 설계

## 기준

런타임 UI는 uGUI로 만든다. UI Toolkit(UXML·USS·UIDocument)은 사용하지 않는다. 모든 화면은 검은 석판, 금빛 테두리, 양피지색 글자와 둥근 모서리 8의 장부형 A안 팔레트(`HudPalette`)를 공유한다.

프리팹과 씬 배치는 에디터 빌더(`Assets/Editor/*Builder.cs`)가 생성한다. `.unity`·프리팹 YAML은 직접 고치지 않는다.

## 시작 화면

시작 전에도 장부와 영업 정보를 한 화면에서 확인한다. 지도 가운데와 아래 가운데는 비워 두고, 상단 양쪽 열에만 정보를 둔다.

- 왼쪽 위 장부(340×268): 일차, 운영 자금, 부채·청산, 마력 막대, 상태 칩 2×2(부활·등급·민심·위협). 부채와 민심은 상세 팝업을 연다.
- 오른쪽 위: 배속 버튼과 일시정지 잠김 사유. 그 아래 손님 브리핑(접힘 380×164)은 일차·방문객 구성·선택 목표를 보여 주고, `자세히`에서 전체 설명을 연다.
- 오른쪽 아래: 목표 전환과 `던전 영업 시작` 버튼을 고정한다.
- 기록판은 "운영 화면을 준비했습니다."와 현재 관리 상태로 시작하고, 이후 침입·시간대 변화를 계속 기록한다.
- 떠돌이 상인은 방문일 대기 시간에 행동 도크에 나타난다. 상점 데이터와 유물 저장은 그대로 유지한다.
- 첫 판 안내 덮개는 강조 구멍과 위쪽 텍스트 카드(머리글·본문·건너뛰기)로 방 선택·설치·영업 시작 순서를 설명한다.

지도 가운데와 아래 가운데는 HUD가 차지하지 않는다. 영업 시작 시에도 상단 배너로 손님 수나 목표를 알려 주지 않는다.

## 계층과 배치

```text
GameplayHud Canvas
├── TopHud
│   ├── Ledger (왼쪽 위, 340×268)
│   └── Speed (오른쪽 위, 216×44)
├── WaveHud
│   ├── Briefing (대기 중, 오른쪽 위, 380×164)
│   ├── Progress (영업 중 브리핑과 같은 자리)
│   ├── ObjectiveButton (오른쪽 아래, 380×40)
│   └── StartButton (오른쪽 아래, 380×72)
└── RecordBoard (오른쪽 열, 위에서 288, 380×360)
    ├── PartyList (스크롤 영역)
    └── ActivityLog (스크롤 영역)
```

`RecordBoard`는 접힌 브리핑 바로 아래에 고정한다. 긴 브리핑을 펼치면 기록판을 숨긴다. 방 상세가 열리면 기록판과 브리핑은 자리를 비우고, 닫으면 브리핑의 펼침 상태에 맞춰 복원한다. 고정 크기 패널은 내용·스크롤바·조건부 텍스트로 크기나 위치가 바뀌지 않는다.

## 구현 원칙

- 색, 테두리, 버튼 상태는 `HudPalette`와 `UiFrameButton`만 사용한다.
- 반복 UI는 `UiKit`으로 만들고, 화면 조립·표시·판단은 각각 Builder·View·Presenter/ViewModel로 나눈다.
- 긴 설명은 고정 HUD에 쌓지 않고 `자세히`, 스크롤 영역, 또는 기존 `PopupController`로 숨긴다.
- 위험·수입·지출 상태만 의미 색을 쓰며, 그 외 본문은 양피지색과 흐린 보조색을 쓴다.

## 검증

- 1280×720과 1920×1080에서 지도 중앙이 비어 있고 시작 버튼과 장부가 겹치지 않는다.
- 빈 기록판, 긴 브리핑, 스크롤바 유무를 바꿔도 카드 경계와 고정 버튼이 움직이지 않는다.
- 시작 직후 장부·브리핑·목표·기록이 각각의 고정 영역 안에 머물고 지도 중앙을 침범하지 않는다.

## 2026-10-26 승인 배치 개선

- 오른쪽 열은 폭 380, 여백 24를 공유한다. 브리핑은 위 104, 기록판은 위 288(380×360)로 고정한다. 목표 전환·영업 시작도 폭 380으로 맞춘다.
- 긴 브리핑을 펼치면 기록판 전체를 숨기고 접으면 복원한다. 방 상세가 열리는 동안의 숨김은 별도로 유지해, 한 상태가 해제되어도 다른 상태의 숨김을 풀지 않는다.
- 왼쪽 아래 도크는 684×112로 줄인다. 기존 버튼·글자 크기는 유지하고 안내 줄·행동 줄·보유 줄 사이 여백만 줄인다. 설치 창·보유 목록·안내 메시지는 새 도크 위 8 간격을 따른다.
- 기존 프리팹과 씬 인스턴스를 그대로 수정한다. 생성기도 같은 치수를 사용하며 화면 전체 재생성은 하지 않는다. 1280×720·1920×1080에서 접기/펼치기·방 상세·설치·목록을 확인한다.

## 2026-10-26 UI 런타임 초기화 안정화

- 어셈블리 재로드에서는 Awake 없이 OnEnable이 다시 실행될 수 있다. 콜백 배열·기록판 표시 캐시처럼 직렬화되지 않는 런타임 값은 OnEnable에서 필요한 경우 재구성한다.
- 기존 필드·프리팹 배선·화면 배치는 유지한다. 콜백은 같은 인스턴스로 구독·해제하고, 재활성화만으로 기존 배열을 다시 만들지 않는다. 초기화 전 비활성화도 안전하게 처리한다.
- 기존 오류 7개 화면과 같은 패턴의 방 상세·설치·지원자·대출 칸을 함께 검사한다. 저장이나 매니저 전체의 재로드 상태 보존은 이번 UI 입력 복구 범위와 구분한다.
- 실제 프리팹의 초기화 전 비활성화, Awake 없는 활성화, 런타임 캐시 소실 후 재활성화, 반복 활성화 시 콜백 중복을 회귀 검증한다. 실제 스크립트 재로드와 타이틀 왕복도 확인한다.
