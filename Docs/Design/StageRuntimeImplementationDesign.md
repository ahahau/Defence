# 고정 스테이지 런타임 전환 구현

2026-10-28 사용자 구현 승인 및 임시 수치 허용. DungeonPathDesign.md·StageDefenseDesign.md·StageLoadoutProgressionDesign.md의 확정 규칙을 구현한다. 테스트/플레이/밸런스 실측은 실행하지 않고 컴파일과 씬 authoring만 한다.

## 전환 방식

기존 SampleScene/방 그래프/구 런 저장은 보존한다. 새 StageDefense 씬에서 고정 맵·코어·스테이지별 웨이브/기믹·편성·스테이지 금화·클리어 영구 강화 흐름을 구성하고 타이틀 새 게임을 이 씬으로 연결한다. 이어하기는 스테이지 준비 저장을 우선하고 없을 때 기존 런 경로를 유지하며 이전 사용자 저장을 삭제/변환하지 않는다. 새 스테이지 프로필은 별도 버전/파일과 백업을 사용하고 기존 메타와 혼합하지 않는다. 새 스테이지는 실패 시 처음부터 재편성하고 준비 단계 체크포인트 이어하기를 추가했다(후속 StageCheckpointDesign.md). 전투 도중 종료하면 마지막 준비부터 해당 웨이브를 다시 시작한다.

## 책임 분리

StageDefinitionSO는 고정 칸/문/코어·웨이브/기믹·임시 수치, StageBoard는 통행/현재 유닛 점유, StagePathfinder는 열린 길 우선 A*와 이동+파괴 시간 비용, StageSession은 준비/진행/완료/실패와 금화/코어·스폰·환급, StageActor는 기존 Unit/Enemy 프리팹의 체력/전투/애니메이션을 재사용하는 근거리 이동 어댑터다. 바리케이드는 Health 기반 회복/파괴 상태와 실제 지불 금액을 보존한다. 함정은 기존 Trap 공격/범위/지속/스탯·효과와 새 스테이지 대상 조회를 연결한다. 편성/영구 강화/프로필·UI는 별도 책임으로 둔다.

길찾기는 프로젝트 내부 A*로 작성하고 새 외부 패키지는 추가하지 않는다. 첫 버전은 네 방향 격자를 사용한다. 열린 우회로가 하나라도 있으면 먼저 사용하고 없을 때만 파괴 가능한 유닛/바리케이드를 공격한다. 파괴 비용은 현재 체력/해당 적 공격 간격·공격력으로 계산하며 다른 적의 동시 타격을 예측하지 않는다. 회복은 피격 중 중단되므로 실제 공격 동안의 회복량은 파괴 비용에 추가하지 않는다. 원래 배치 자리가 아니라 현재 위치만 동적 차단하고 쓰러지면 즉시 해제한다.

## 임시 콘텐츠와 수치

초기 실행용 스테이지/웨이브·코어 체력·초기 자금·공용 편성 슬롯·추적/교전 범위·바리케이드 가격/체력/회복 대기/회복량/두 환급률·초회 클리어 강화 보상/강화 가격·최대 단계는 에셋에 기록한다. 모두 사용자 허용 임시 수치이며 밸런스 확정값이 아니다. 환급은 실제 설치비에 각 비율을 곱해 내림한다. 영구 보상은 초회 클리어만 지급하는 임시 정책으로 중복 지급을 막는다. 영구 강화는 종류별 직접 공격/함정 피해 강화의 첫 버전이며 기존 스킬/유물/명령 전체의 새 격자 전환 완료를 의미하지 않는다.

새 UI는 기존 어두운 던전 팔레트/TMP/uGUI를 따른다. 준비 중 편성·구매/철거·강화, 전투 중 코어/금화/웨이브·남은 적, 완료/실패 때 다음 스테이지/재도전으로 구분한다. 기존 UI를 재생성하지 않고 새 씬에 전용 UI를 구성한다. 씬/에셋은 Unity API로 작성하고 미저장 기존 씬은 저장/폐기하지 않는다.

## 현재 규모와 기믹

고정 스테이지 7개, 부하 9종/함정 7종이며 편성 UI도 16줄이다. 기본 슬롯 4개에 2·4 스테이지 초회 클리어마다 1개씩 늘어난다. 1 연습 → 2 도중 문 개방 → 3 설치 불가/강화 칸 → 4 환경 장치 → 5 표식 적 → 6·7 조합으로 진행하며 마지막 웨이브에 서로 다른 보스와 호위가 나온다. 스킬 자동·궁극기 수동, 경로 표시·설정/배속도 반영했다. 상세 후속 기록은 아래 기능별 절을 따른다.

## 함정 확장분 편성 추가 (2026-10-28)

사용자 결정: 함정 넷을 편성 선택지에 더하고, 마력·충격 수정은 처음부터, 노출 수정·번개 구름은 Stage_01 클리어 뒤에 푼다. 편성 목록은 스크롤 목록으로 바꾼다.

- `StageDefenseBuilder.AddExpansionTraps()`: 카탈로그에 없는 선택지만 뒤에 붙인다(기존 6개·순서·수치 그대로, 6 → 10). 새 카탈로그를 만들 때(`BuildData`)도 같은 함수를 부른다.
- `StageDefenseBuilder.RebuildOptionList()`: 이미 작성된 StageDefense 씬의 `Option_*` 줄을 지우고 예전 6줄 자리(위 240~840)에 스크롤 목록(`OptionList`, `UiKit.ScrollArea` + 세로 배치, 줄 90·간격 10)을 만들어 `StageHudView.rows`에 다시 잇는다. 씬이 열려 있고 저장하지 않은 변경이 있으면 멈춘다. 새 씬 작성(`BuildHud`)도 같은 목록을 쓴다. 고정 6줄일 때 선택지가 늘면 HUD가 넘친 선택지를 묶지 않아 조용히 사라졌다.
- `StagePlacement`: 여러 칸 함정을 덮은 칸만큼 늘린다(방 격자 `NodeTrapGrid.TryPlace`와 같음). 전에는 칸 크기만 곱해 번개 구름이 2×2를 치면서 그림은 한 칸이었다.
- 확인(에디트 모드만): 선택지 10개·해금 조건, 씬 줄 10개·줄 참조 누락 0·누락 스크립트 0·스크롤 있음. 바꾸기 전 카탈로그·씬은 `tmp/stage-traps-20261028`에 백업했다. 플레이·테스트는 하지 않았다.
- 볼 점: 번개 구름은 범위 안 부하도 치는데(기존 함정 규칙) 영구 강화 배율이 그 아군 피해에도 곱해진다(`Trap.HitUnits`).

## 일시정지·배속·설정 (2026-10-28)

사용자 선택: 후속 목록 중 일시정지·배속·설정을 먼저 연결한다. 새 화면을 만들지 않고 SampleScene의 것을 재사용한다.

- `GameSpeedController`를 StageDefense 씬에 하나 둔다(기본 1배). 스페이스 일시정지·1/2 배속 단축키가 그대로 동작한다.
- 설정 화면 프리팹(`SettingsBuilder.PrefabPath`, 프리팹 연결 유지)을 놓는다. 붙어 있는 `UiEscapeRouter`는 이 씬에 다른 창이 없어 목록이 설정 하나다 — ESC로 열고 닫는다. 열린 동안 시간을 멈춘다.
- 설정 화면의 "다시 시작"은 구 런 저장을 지우고 SampleScene으로 가므로 스테이지 씬에서는 숨긴다(`SettingsScreenView.allowRunRestart`, 기본 참이라 SampleScene은 그대로). 재도전은 스테이지 HUD의 "스테이지 재도전"을 쓴다. "타이틀로"는 배속을 되돌린 뒤 이동한다.
- 스테이지 HUD 오른쪽 위(1480~1888, 위 28)에 일시정지·1배·2배·설정 버튼. 고른 배속만 금색 테두리이고 단축키로 바꿔도 `SettingChanged`로 맞춘다. 버튼 자리를 위해 제목·상태 글 폭을 1400 → 990으로 줄였다. HUD의 "타이틀" 버튼도 배속을 먼저 되돌린다(`ResetToNormal`).
- 생성기: `StageDefenseBuilder.AddSpeedAndSettings()`(이미 작성된 씬, 이미 있으면 배선만 다시), 새 씬 작성(`BuildScene`)도 같은 함수들을 쓴다. 씬 열기·저장은 `EditScene`으로 모았다(저장 안 된 변경이 있으면 멈춤).
- 확인(에디트 모드만): HUD 배선 6칸·설정 화면 배속 연결·다시 시작 숨김·라우터 설정 연결·씬 안 배속 컨트롤러/설정/라우터 각 1개·누락 스크립트 0·제목 폭 990. 바꾸기 전 씬은 `tmp/stage-speed-20261028`에 백업했다. 플레이·테스트는 하지 않았다(버튼 모양·겹침·실제 키 입력 미확인).
- 남은 것: 엘리트·보스 일시정지 잠금(`SetPauseLock`)은 스테이지 웨이브가 아직 걸지 않는다. → 보스는 아래 "보스 웨이브", 정예는 2026-11-01 [스테이지 정예 투입](StageEliteDesign.md)에서 걸었다.

## 해금표·슬롯 확장 (2026-10-28)

사용자 승인: 구현 묶음 A. 기획은 `StageDefenseDesign.md` "해금 배정"을 따른다. 위 "작성된 콘텐츠와 임시 설정" 표의 편성·부하·함정 줄은 이 절로 대체한다.

- 편성 슬롯은 스테이지 에셋이 아니라 진행에서 계산한다. `StageCatalogSO.BaseLoadoutSlots`(4) + `SlotRewardStages`(Stage_02, Stage_04) 중 처음 깬 수(`StageProfile.LoadoutSlots`, `StageSession.LoadoutSlots`). `StageDefinitionSO.LoadoutSlots`는 지웠다(기존 에셋 YAML에 남은 값은 읽지 않음).
- 카탈로그 선택지 16개: 시작 해골 방패병·해골 검사·속박 수정·불 화로 / Stage_01 늑대 기수·뼈 궁수·마력 수정 / Stage_02 충격 수정·핏빛 웅덩이 / Stage_03 해골 주술사·오크 철퇴병 / Stage_04 해골 저격수·노출 수정 / Stage_05 오크 주술사·번개 구름 / Stage_06 망령 암살귀. 선택지 ID는 에셋 GUID라 기존 강화 기록이 이어진다. 기존 6종 중 철퇴병·핏빛 웅덩이·마력/충격·노출·번개 구름의 해금 시점이 바뀌었다.
- 잠긴 줄은 "N 스테이지 클리어 필요"로 보인다(`StageCatalogSO.StageLabel`). Stage_03~06은 아직 없어서 ID가 그대로 보이고 그 해금은 실제로 풀리지 않는다 — 7개 스테이지를 만들 때(묶음 C) 풀린다.
- 작성기: `StageDefenseBuilder.ApplyUnlockTable()`(선택지·슬롯을 표대로 다시 씀, 강화 비용/상한/배율은 그대로). `AddExpansionTraps`는 이 함수로 대체해 지웠다. 씬 편성 목록은 `RebuildOptionList()`로 16줄.
- 확인(에디트 모드만): 재컴파일 오류 0, 선택지 16·해금 조건 표와 일치, 기본 4·보상 스테이지 둘, 씬 줄 16·줄 참조 누락 0·누락 스크립트 0, 새 부하 6종 프리팹·Combatant 있음. 바꾸기 전 카탈로그·스테이지·씬은 `tmp/stage-unlocks-20261028`에 백업했다. 플레이·테스트는 하지 않았다.
- 볼 점: 해골 검사 프리팹만 `SkillCaster`가 없다(스킬 연결 묶음 D에서 볼 것). 새 부하 6종이 스테이지 이동 어댑터에서 제대로 움직이는지는 플레이로 확인하지 않았다.

## 부하 복귀 자리 막힘 (2026-10-28)

사용자 승인: 구현 묶음 B. 기획은 `StageDefenseDesign.md` "질문 확정"의 복귀 자리 막힘 줄을 따른다.

- 전에는 상대가 없으면 원래 자리로만 길을 찾았고, 자리가 막혔거나 길이 없으면 그 자리에 멈춰 기다렸다(경로 없음 → 정지, 다음 칸에 아군 → 매 프레임 재탐색).

작성 소스는 `Assets/01.Code/Stages/`(진행/맵/점유/A*/설치/캐릭터 어댑터/프로필/UI)와 `Assets/Editor/StageDefenseBuilder.cs`다. 기존 코드 수정은 EnemyDataSO의 별도 도달 피해, Trap의 새 대상/칸 크기/강화 연결, 비활성 구 BattleAgent의 회피 이동 방지, TitleMenuActions의 새 게임 경로다. 새 씬·바리케이드 프리팹·스테이지/카탈로그와 빌드 목록은 Unity API로 작성했다. 기존 씬 저장과 YAML 직접 편집은 하지 않았다.

현재 스킬 자동·유닛별 궁극기 수동·보스/호위·설정/일시정지/배속·경로 표시·문/칸/표식 적·환경 장치는 반영됐다. 구 노드 BT/BattleAgent의 자동 이동만 비활성화하고 SkillCaster의 효과/쿨다운은 StageActor가 사용한다. 준비 단계 체크포인트와 타이틀 이어하기는 추가했다. 유물은 스테이지로 옮겼다(아래 "스테이지 유물"). 적 파티 동행도 옮겼다(아래 "스테이지 적 파티 동행"). 부하 명령은 이동 범위 3종으로 새로 만들었다(아래 "스테이지 부하 명령"). 정예는 Stage_03부터 보스 직전 웨이브에 넣었다([스테이지 정예 투입](StageEliteDesign.md)). 추가 콘텐츠는 후속이다. 막힌 복귀 자리는 근처 도달 가능한 빈 칸에서 대기한다. 파괴 시간은 치명타/협공 예측을 생략한 근사다.

초기 2개 버전의 확인 기록은 Runtime/Editor 빌드·Unity 재컴파일 오류 0과 편성 행 6·스테이지 2였다. 이후 후속 작업으로 스테이지 7/선택지 16이 됐으며 최신 정적 점검은 Docs/AI/StageRuntimeReview-20261028.md를 따른다. 테스트/플레이/프리뷰/밸런스 실측은 하지 않았다. 근거·기존 수정 파일 백업은 tmp/stage-runtime-20261028에 남긴다.

## 정적 리뷰 3건 수정 설계 (2026-10-28, 사용자 작업 재개 승인)

- 스테이지 스킬 이동은 ISkillMovement와 별도 StageSkillMovement가 맡는다. 스킬 대상은 SkillContext.Target을 사용하고, 구 SampleScene은 Field에 이동 인터페이스가 없을 때 기존 호출을 유지한다.
- 대시는 선분을 따라 유효한 통행/점유·부하 추적 반경을 확인하고 막히기 전 지점까지만 간다. 후방 순간이동은 착지점과 중간 지형이 유효할 때만 실행하며 실패하면 후방 타격/상태 효과도 실행하지 않는다. 후방 이동 중에는 해당 타깃 몸을 통과할 수 있지만 착지점은 다른 전투원과 겹치지 않는다. 두 방식 모두 고정 벽/닫힌 문을 통과하지 않으며 바리케이드는 도약 규칙 적만 기존 규칙대로 무시한다.
- 실제 이동 뒤에는 현재 경로/복귀 목표 재검사와 그림의 이동 추적을 초기화한다. 이미 쓰러진 전투원이나 전투 단계 밖에서 이동 스킬을 실행하지 않는다. 새 스테이지의 속박은 일반 이동과 스킬 이동 모두 차단한다. 구 SampleScene의 대시 동작은 바꾸지 않는다.
- StageActor 일반 이동은 BattleAgent.IsCombatMoveLocked를 확인해 기존 속박/이동 잠금을 반영한다. 닫힌 환경 문은 통행뿐 아니라 CanSee에도 반영한다.
- 맵·데이터·밸런스 수치는 바꾸지 않고 테스트/플레이 없이 컴파일만 확인한다. 신규 인터페이스/서비스 파일의 검증에도 사용자 테스트 금지가 우선한다.

수정 반영 결과: 인터페이스/이동 서비스 추가 및 기존 스킬 효과 2개·StageActor·StageSkillField·CanSee 연결을 완료했다. 이동 서비스는 프레임별 새 객체/목록을 만들지 않는다. Runtime/Editor 빌드·Unity 재컴파일 오류 0, 현재 편집기 콘솔 오류 0을 확인했다. 테스트/플레이는 미실행이며 스테이지/프리팹/수치·사용자 저장 변경은 없다. 후방 착지가 불가한 경우 효과 조각은 실행하지 않지만 기존 스킬 시도/쿨다운 소비 정책은 유지한다. 지대/광역 효과의 벽 관통 정책은 이번에 변경하지 않았고 교전 대상 시야 검사만 고쳤다.

## 웨이브 결과 요약 (2026-10-29)

사용자 승인으로 StageWaveResults/StageWaveReport/StageWaveResultPresenter를 분리하고 처치·도달·실제 코어 손실·전투 금화(파괴 환급 포함), 실제 클리어 강화 재화와 다음 행동을 기존 HUD에 표시한다. 준비 체크포인트 v1의 선택 필드로 마지막 완료 결과를 보존하고 없는 구 저장은 요약을 생략한다. 금화/보상/복구 규칙과 종료/백업 보호 계약은 유지한다. 발견된 커서 종료 예외에 null 검사를 추가했다. 최종 Runtime/Editor 빌드 오류 0, 결과 요약 Unity 재컴파일 통과. 마지막 커서 보완의 Unity 재요청은 플레이 중 HTTP 400으로 거부돼 최종 재검증 미확인이다. 콘솔에는 관리자 중복/기존 저장 검증 실패/보완 전 커서 오류 기록을 유지했고 테스트·플레이 조작·저장 왕복은 실행하지 않았다. 상세 [웨이브 결과 설계](StageWaveResultDesign.md).
