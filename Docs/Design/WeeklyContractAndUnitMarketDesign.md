# 주간 계약과 유닛 상점 설계

## 목표

청산은 단순히 빚을 자동 차감하는 화면이 아니라, 다음 주의 위험을 감수할 계약과 부하를 고르는 유일한 경영 창구다. 영업 중에는 계약과 고용을 바꾸지 않는다.

## 계약

- 대출 상품은 이름, 한도, 주간 이자, 최소 원금 상환율, 계약 기간(주), 중도 변경 수수료와 특약 설명을 가진다.
- 계약 기간이 남아 있는 동안에는 현재 상품을 유지한다. 빚이 0일 때만 청산 화면에서 중도 변경할 수 있고 수수료를 즉시 낸다.
- 계약이 끝나는 청산일에는 빚이 있으면 현재 상품을 연장한다. 빚이 없으면 후보 중 하나를 선택하거나 현재 상품을 연장한다.
- 초기 데이터는 기간 1주, 중도 변경 수수료 0, 특약 없음으로 동작한다. 이후 기관별 특약과 실적 기반 조건 갱신은 같은 데이터 구조에 추가한다.
- 계약 선택과 남은 기간은 런 저장에 포함한다. 기존 저장은 현재 상품의 새 1주 계약으로 복원한다.

## 유닛 상점

- 유닛 판매 목록은 청산일에만 새로 만들고 다음 청산일까지 유지한다. 영업 중에는 고용할 수 없다. 새 판 시작 때도 같은 규칙으로 첫 주 목록을 만들어 시작 지원자에 더한다(2026-10-21 사용자 결정).
- 고용은 영업 전 대기 중이면 언제든 할 수 있다(2026-10-21 사용자 결정, 도크 "고용" 버튼 → 고용 창). 청산일 정산표의 유닛 상점도 그대로 쓴다. 예전에는 청산일에만 고용돼 첫 주에 부하를 둘 방법이 없었다.
- 이번 단계의 목록은 기존 해금 유닛·지원자 특성/성격 데이터를 그대로 사용한다. 등급·레벨·희귀도 가격 보정과 능력 툴팁은 해당 데이터가 확정될 때 추가한다.
- 목록의 지원자를 고용하면 즉시 운영 자금을 차감하고 보유 명단으로 옮긴다. 고용하지 않은 지원자는 다음 청산 때 목록 교체와 함께 사라진다.
- 목록과 지원자의 특성/성격/기한은 저장·복원되어, 같은 주에 저장을 다시 불러도 달라지지 않는다.

## 검증

- 영업 중 고용 거절, 대기 중·청산일 고용 승인, 다음 청산의 목록 교체를 EditMode로 검증한다.
- 빚이 남은 청산일에는 상품 변경이 막히고, 빚이 없는 청산일에는 변경되는지 검증한다.
- 계약 기간·선택 상품·판매 목록이 저장 뒤 복원되는지 검증한다.

## 2026-10-26 시세 등급 표시 기준 승인

- 저렴/보통/비쌈은 원래 배율이 아니라 화면에 표시되고 실제로 결제하는 정수 고용가를 정가와 비교해 판정한다. 정가 대비 10% 이상 저렴하면 저렴, 10% 이상 비싸면 비쌈이다. 경계의 정가 비율 자체는 반올림하지 않는다.
- 정가 100G에서 배율 0.904→90G는 저렴, 1.096→110G는 비쌈이다. 정가 1G의 0.75~1.25배가 실제로 1G면 보통이다. 무료·정가 0 이하는 보통으로 표시한다.
- 가격 배율 범위·반올림·최소 가격·유지비·지원자 생성·저장 형식·결제 경로는 유지한다. 비교에는 정수 비율을 사용해 부동소수점 경계 오차를 피한다.
- 난수 의존 검사 대신 고정 배율로 경계 안팎·소액·무료·옛 저장 기본 배율을 재현하고, 실제 고용 화면 문구·색과 결제 금액을 확인한다.
