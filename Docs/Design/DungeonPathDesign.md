## 2026-10-28 초기 구현 반영

사용자가 지금까지 확정한 규칙의 구현과 미정 수치의 임시 설정을 승인했다. 새 `Assets/00.Scenes/StageDefense.unity`와 `Assets/01.Code/Stages/`에 초기 런타임을 작성했다. 타이틀 새 게임은 빌드 목록에 있는 StageDefense로 들어가고, 기존 이어하기는 SampleScene을 유지한다. 기존 런/메타 파일을 삭제하거나 변환하지 않는다.

- 고정 맵/문/코어·기믹·웨이브 에셋, 열린 길 우선 내부 네 방향 A*, 완전 차단 시 이동+파괴 예상 시간, 현재 유닛 위치 점유·사망 시 해제, 제한 추적/복귀·근거리 교전을 연결했다.
- 코어 도달 피해 한 번 후 제거(처치 보상 없음), 웨이브 사이 코어 체력 유지, 코어 0 실패와 처음부터 재편성, 부하 웨이브 종료 복구를 연결했다.
- 체력/무피격 후 회복·파괴/즉시 철거와 실제 지불액 기준 1회 환급, 준비 전용 구매/배치/철거를 연결했다.
- 공용 편성·허용 종류 검증·영구 피해 강화·초회 클리어 보상·다음 스테이지 해금을 연결했다. 처음 배치 전에만 해당 판에 적용할 강화를 구입할 수 있으며 결과 화면에서는 다음 공략을 위해 강화할 수 있다. 편성은 첫 웨이브 전까지 변경 가능하되 이미 배치한 종류를 빼려면 먼저 회수/철거해야 한다.
- 새 프로필 `defence-stage-profile-v1.json`은 단계 해금/강화/재화를 별도 버전/원본/백업으로 보존한다. 보상/강화는 파일 교체 성공 후 상태를 확정하고, 읽기 실패 시 원본/백업을 보호한다. 스테이지 도중 체크포인트 이어하기는 아직 제공하지 않는다. 이번 작성 과정에서 사용자 프로필을 생성/수정하지 않았다.
- 현재 기존 프리팹의 체력·스탯·평타·애니메이션·함정 효과를 재사용한다. 노드 전체 탐색을 막기 위해 구 BattleAgent/Behavior 그래프·SkillCaster 자동 구동은 새 스테이지 생성물에서 끈다. 기존 스킬·유물/명령·파티 동행·보스 전용 기능 전체의 단일 격자 재연결은 후속 작업이다. 기존 SampleScene 구현은 보존한다.
- 복귀 칸이 막혀 있으면 통과/순간이동하지 않고 대기한다. 이동 경로는 0.25초마다 재평가하고 동료와 최소 간격을 둔다. 파괴 시간은 체력과 방어 적용 후 적 피해/공격 간격을 사용하며 치명타/동료 협공 예측은 생략한 초기 근사치다.

플레이와 테스트를 실행한 완료 근거는 없다. 런타임/에디터 코드 빌드와 Unity 재컴파일 오류 0, 저장된 새 씬의 누락 스크립트/편성 행 참조 0만 확인했다. 상세 구현/임시 수치는 [런타임 구현 기록](StageRuntimeImplementationDesign.md)을 따른다.

> 작은 방 노드 연결에서 단일 맵의 길 설계로 공간 기획을 전환한다. 현재 코드/씬은 여전히 다중 노드 구현이며 이번 작업은 기획 문서만 수정한다. 아래 조작/전투 세부는 기준안이고 수치·예외 정책은 구현 전 확정한다.

## 확정된 스테이지 공간과 조작

2026-10-28 후속 사용자 결정으로 기존 자유 길 파기 기준안을 아래 규칙으로 대체한다. 종전 문서의 “열린 길이 없으면 시작 금지/파괴 이동은 추가하지 않음” 방침도 폐기한다. 기존 파일명은 참조 호환용으로 유지한다. 이전 메인 금고 방어 목표는 앞으로 코어로 부른다. 예금 금고와는 다른 방어 목표다.

- 스테이지는 사전에 제작한 하나의 연속 맵이다. 기본 지형·던전문·코어 위치와 스테이지별 기믹은 스테이지 데이터에 정해져 있다. 플레이어가 던전문/코어를 이동시키거나 지형을 파지는 않는다. 문 개수·좌표·기믹 종류는 각 스테이지 설계에서 정한다.
- 플레이어는 정해진 설치 가능 영역에 바리케이드·유닛·함정을 배치해 적의 동선과 교전 지점을 만든다. 작은 방 구매/연결·개별 시설 정원 관리로 돌아가지 않는다.
- 바리케이드와 살아 있는 배치 유닛은 적의 통행을 차단한다. 바닥 함정은 통행 가능하다. 시각적 겹침 회피와 길찾기 차단 여부는 구분한다. 유닛이 쓰러지면 즉시 그 자리는 통행 가능해지고 유닛은 웨이브 종료 후 복구한다.
- 바리케이드는 편성 슬롯을 사용하지 않는 기본 도구이며 설치할 때 스테이지 금화를 지불한다. 부하/함정의 가져갈 종류 제한은 [편성 설계](StageLoadoutProgressionDesign.md)를 따른다.
- 구매·배치·철거는 준비 단계에서만 가능하다. 웨이브 중 경로 변화는 공격에 의한 파괴 등 실제 전투 결과로 발생한다. 전투 중 플레이어의 재설치/철거를 허용하지 않는다.

## A* 이동과 차단·파괴

- 적은 A*를 사용해 던전문에서 고정된 코어 도달 위치까지 가장 빠른 통행 경로로 이동한다. 첫 버전은 외부 패키지 없는 내부 네 방향 격자 A*이며 정확한 크기/사거리·추가 이동 확장은 별도다.
- 열린 우회로가 있으면 파괴 없는 우회 경로를 우선한다. 파괴하면 더 짧다는 이유만으로 열린 경로를 버리고 지름길을 뚫는 규칙은 현재 채택하지 않는다.
- 코어까지 열린 경로가 완전히 끊겼다면 적은 차단물을 공격해 길을 뚫는다. 이 경우 이동 시간과 파괴 예상 시간을 합쳐 코어에 가장 빨리 도착하는 경로를 선택한다. 단순 직선 거리나 가까운 장애물만으로 정하지 않는다.
- 파괴 경로에는 해당 적이 실제로 공격/파괴할 수 있는 차단물만 후보로 넣는다. 유닛 교전·공격 사거리·바리케이드 체력/회복과 다수 적의 공동 공격을 예상 시간에 어디까지 반영할지는 추가 설계 대상이다.
- 고정 지형 전부를 파괴 가능하다고 가정하지 않는다. 고정 벽/기믹 지형의 파괴 가능 여부는 스테이지/오브젝트 규칙으로 구분한다. 파괴 가능한 차단물까지 포함해도 코어에 도달할 수 없는 맵/배치는 유효하지 않다. 코어/던전문 자체를 덮거나 삭제하는 배치는 허용하지 않는 기준안이다.
- 배치/철거·차단물 파괴·유닛 통행 상태 변화로 길이 열리거나 막히면 실제 이동과 경로 안내가 같은 통행 데이터를 사용해 경로를 갱신해야 한다. 갱신 주기·선택 경로 변경 기준은 후속 결정한다.
- 열린 길이 없다는 사실만으로 웨이브 시작을 거절하지 않는다. 파괴로 개척할 수 있는 경로인지와 일반 통행 경로인지를 구분한다. 길 차단을 순간이동/무적 통과로 해결하지 않는다.

## 바리케이드 체력과 자동 회복

사용자 확정:

- 바리케이드는 체력을 가지며 마지막 피격 후 일정 시간 동안 피해를 받지 않으면 자동 회복한다. 다시 피격되면 무피격 대기 시간을 다시 센다. 최대 체력을 넘겨 회복하지 않는다.
- 체력이 0이 되면 무너져 길이 열리고, 실제 설치비의 일정 비율을 금화로 돌려준다. 자동으로 되살아나는 규칙은 추가하지 않는다. 다시 설치하려면 준비 단계의 구매/배치 규칙을 따른다.
- 플레이어 철거는 준비 단계에서 즉시 완료되며 실제 설치에 쓴 금화 일부를 돌려준다. 별도 철거 대기 시간이나 추가 철거 비용은 두지 않는다.
- 파괴 환급률과 철거 환급률은 별도로 정할 수 있으며 두 비율이 같다고 가정하지 않는다. 환급은 해당 바리케이드 제거 사유에 맞춰 한 번만 지급한다. 철거와 파괴가 겹쳐 이중 환급하지 않는다.
- 환급 기준은 표시 정가가 아닌 실제 지불한 설치 금화다. 할인 설치 뒤 정가를 기준으로 더 많은 금화를 돌려받는 규칙으로 만들지 않는다.

최대 체력·무피격 대기 시간·회복량/간격·금화 가격·각 환급률/소수점 처리·업그레이드 대상 여부는 미정이다. 철거/파괴 환급은 스테이지 금화이며 영구 강화 재화나 클리어 보상으로 집계하지 않는다.

회복하는 차단물을 영원히 공격해 웨이브가 끝나지 않는 상황은 수치/적 공격·공략 가능성 설계에서 다뤄야 하며 이번에 임의 수치를 넣지 않는다. 파괴 예상 시간에 자동 회복을 반영하는 정도와 다수 적의 공동 공격은 후속 설계 대상이다.

## 코어 도달

적이 코어에 실제 도달하면 피해를 한 번 주고 사라진다. 코어 앞에서 반복 공격하는 방식은 채택하지 않는다. 코어 피해와 적 제거/웨이브 잔여 수 차감은 한 번만 처리한다. 도달로 사라진 적을 처치 보상으로 집계하지 않는 기준안이다. 코어의 남은 체력은 같은 스테이지의 다음 웨이브에도 그대로 이어지며 웨이브 사이에 자동 회복하지 않는다. 새 스테이지에 들어갈 때 초기화한다. 코어 도달 피해는 적 종류별 별도 값으로 지정하며 적의 현재 공격력과 연동하지 않는다. 코어 체력이 0이면 패배한다. 재도전은 실패한 웨이브가 아니라 해당 스테이지 처음부터 시작하고 편성을 다시 선택할 수 있다. 스테이지 초기화 규칙에 따라 코어·판 안 금화·배치를 초기 상태에서 시작하며 기존 해금·영구 강화 기록은 유지한다. 코어 최대 체력·적별 도달 피해 수치는 아직 미정이다. 실패 보상은 StageDefenseDesign 표의 2026-11-02 결정을 따른다.

## 부하·함정·적 이동

- 부하는 맵의 유효한 배치 칸에 둔다. 기존 방별 팀 정원을 그대로 단일 맵 전체 한도로 적용하지 않는다. 유닛은 배치 지점 주변의 짧은 범위 안에서만 적을 추적하고 전투 후 원래 배치 지점으로 복귀한다. 무제한 추적하지 않는다. 정확한 추적 거리는 임시 값이다. 범위 이탈 시 해제·막힌 복귀 자리·전체 배치 한도(없음)는 아래 2026-10-28 확정을 따른다. 플레이어의 재배치는 준비 단계에만 가능하다. 유닛이 이동하면 현재 위치가 통행을 막고 원래 배치 지점은 열린다. 원래 지점에 보이지 않는 고정 차단물을 남기지 않는다. 복귀 지점에 적/다른 유닛이 있으면 가까운 빈 칸에서 기다린다(2026-10-28 확정, 구현됨).
- 적은 A*로 고정 코어를 향하며, 길이 열려 있어도 가까운 아군 유닛이 교전 범위에 들어오면 싸우고 전투 후 코어 이동을 재개한다. 직접 길을 막는 유닛만 공격하는 방식은 아니다. 코어까지 완전 차단되면 파괴 경로를 사용한다. 정확한 교전 범위·대상 선택 우선순위·교전 해제 조건은 아직 미정이다. 전열/원거리/지원/정예 역할과 기존 그림·스킬은 재사용한다.
- 함정은 실제 점유 칸과 적의 통행 칸을 사용한다. 경로 미리보기는 실제 길찾기와 같은 데이터에서 계산한다. 방 중앙 슬롯이나 방을 옮겼다는 이벤트로 발동을 대신하지 않는다.
- 파티 동행·겹침 해소는 재사용하되 방을 하나씩 독점하고 문에서 대기하는 흐름은 연속 경로의 국소 혼잡 처리로 재검토한다. 화면 밖 적까지 전체 던전 입장을 막지 않게 한다.

## 남은 세부 결정

- 2026-10-28 확정(상세 [StageDefenseDesign.md](StageDefenseDesign.md) "질문 확정"): 복귀 자리가 막히면 가까운 빈 칸에서 기다렸다가 돌아간다. 적은 교전 범위 안 가장 가까운 아군을 친다. 전체 배치 한도는 두지 않고 금화로만 제한한다.
- 교전 해제: 적이 배치 자리 기준 추적 반경을 벗어나면 바로 포기하고 복귀한다(확정). 추적/교전 거리 수치는 미정.
- 기믹: 문 여러 개·도중 개방, 설치 불가/강화 칸, 환경 장치, 스테이지 한정 적 특수 규칙을 모두 쓴다(확정). 스테이지별 배정은 미정.
- 유닛 현재 위치의 동적 차단과 근거리 적의 접근/공격 위치 확보, 경로 재탐색 주기.
- 고정 스테이지의 개별 기믹과 웨이브 편성, 파괴 불가 지형/설치 가능 영역.
- 바리케이드 회복/환급·코어/도달 피해·편성/영구 강화 수치(실패 보상은 2026-10-28 없음 확정 → 2026-11-02 막은 웨이브 수 비례로 변경, StageDefenseDesign 표).

아직 질문하지 않은 세부는 미정으로 남기며 기존 코드값이나 추천을 확정값으로 사용하지 않는다.

## 단일 노드로 전환할 때 반드시 재설계할 의존성

| 기존 방/노드 기준 | 단일 맵에서 필요한 판단 |
|---|---|
| NodeBattlefield.HasOpponents/방 전체 적 명단 | 거리·실제 접근 가능성 기반의 근거리 교전 후보. 맵 끝 적을 발견해 전 부하가 달려가지 않게 함 |
| 방별 maxPerTeam/Node 점유 | 맵 배치 한도와 근거리 충돌/혼잡. 과거 소형 방 정원이 던전 전체 한도가 되지 않게 함 |
| 문→설 자리의 방 안 이동/노드 간 이동 | 하나의 연속 경로와 실제 배치 위치. 금고 도달을 맵/노드 진입과 구분 |
| 같은 방 대상 치유·광역 기술 | 실제 거리/범위와 접근/벽 정책. 전체 맵 치유·공격이 되지 않게 함 |
| 방 방문 N회 상태이상 | 지속 단위 재설계 전 보류. 금고까지 방을 옮기지 않아 영구 유지되는 효과를 만들지 않음 |
| 인접 방 적 없음 등 유물 조건 | 칸/거리/국소 교전으로 조건을 다시 정의하거나 후보 제외. 숫자 단순 치환 금지 |
| 방별 부하/시설/풍요·요새·함정 지대 | 기본판에서 방 단위 확률 보정/관리 제외, 필요한 전투 지형 효과만 별도 기획 |
| 노드 확장 후보/공사·철거/방 금액 | 통행 칸 편집과 배치 유효성. 방 구매/연결 관리로 되돌리지 않음 |
| 노드 기반 저장·카메라·방 상세/위협 거리 | 단일 격자/입구/금고/지형 편집/배치 저장과 칸 선택·도달 거리 안내 |

현재 NodeBattlefield는 팀 명단/정원을, BattleAgent는 그 상대 명단을 사용한다. 외형 크기만 키우는 작업으로 끝내지 않고 위 계약을 함께 전환해야 한다. 구현 중 내부적으로 영역 조회나 공간 분할을 쓰더라도 플레이어가 관리해야 하는 여러 방 노드를 다시 만들 필요는 없다.

## 화면과 보상

준비 도크는 편성 확인·바리케이드/부하/함정 배치·침입 시작을 중심으로 한다. 방 후보 구매/시설 운영 상세는 제외 대상이며 칸/부하/함정 선택 상세를 사용한다. 상시 정보는 금고 상태·금화·웨이브/남은 적이다. 바리케이드/부하/함정 가격·보상은 미정이며 경영 제거를 보상하기 위한 새 유지비나 관리 자원을 도입하지 않는다.

## 단계와 저장

1. 단일 맵·입구/금고·통행 칸/도달 경로의 상태 계약을 정한다.
2. 실제 이동·근거리 교전·배치/혼잡·범위 기술·경로 표시를 같은 좌표/단위로 전환한다.
3. 금고 실패/도달 종료·처치/웨이브 보상·경영 진입점 제외를 연결한다.
4. 배치/차단/파괴 경로 UI·튜토리얼·노드 의존 상태/유물·카메라·저장 포맷을 정리한다.

구 노드 저장을 단순히 하나의 대형 방으로 읽지 않는다. 이전 런 변환/새 판 지원 정책은 미정이며 사용자 런·백업·메타를 임의 삭제하지 않는다. 이번 문서 개정에서 코드·씬·에셋 변경과 빌드/테스트/플레이/프리뷰는 하지 않는다.
