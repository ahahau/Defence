# 스테이지와 웨이브에 맞는 준비 안내

2026-10-29 사용자 승인: 실제 장치/특수 적만 설명하고 현재 입구 수·추가 개방 시점을 안내하며 기존 배치/결과 문구와 중복을 줄인다. 테스트·플레이 조작·밸런스 실측은 실행하지 않는다.

## 표시안

기존 상단 상태와 하단 Tool 텍스트를 사용한다. 중앙 패널/새 버튼·씬/프리팹 변경은 없다. 왼쪽 안내의 저장 오류/피격 안내/웨이브 결과/조작 피드백 우선순위는 유지한다.

```text
상단: 코어 ... 금화 ... 웨이브 1/3 ... 입구 2/3 · 3웨이브에 +1
하단: 바리케이드 10G · 우클릭 취소 | 경로 색 안내
      표식 적: 주황 도약(바리케이드 넘음)
      장치: 주황 불(아군도 피해) · 회색 문(주기 차단) · 낙석(금색일 때 누름)
```

예시는 배치를 설명한 문안이다. 실제 Tool 영역은 기존 1400×38을 유지하고 기본 18pt 상한/14pt 하한 자동 맞춤과 줄바꿈을 사용한다. 상단 상태도 기존 990×42를 유지하고 기본 22pt 상한/16pt 하한 자동 맞춤과 줄바꿈으로 입구 예고 공간을 확보한다. 실제 줄바꿈/가독성은 플레이나 프리뷰를 실행하지 않아 미검증이다.

## 데이터와 문구

- 준비/전투의 입구 수는 StageDefinitionSO.OpenDoorCount로 계산한다. 이번 웨이브에 새로 열린 수는 직전 웨이브와의 차이로 표시한다. 준비 단계에서 아직 남은 개방이 있으면 가장 가까운 개방 웨이브와 추가 입구 수를 예고한다. 없는 미래 개방을 만들거나 모든 입구가 열렸을 때 불필요한 경고를 붙이지 않는다.
- 특수 적은 일반 적의 유효 스폰 인덱스만 RuleAt으로 읽는다. Vault/Rush를 각각 한 번만 안내하고, 이번 웨이브에 없는 규칙과 보스/호위에 적용되지 않는 규칙은 표시하지 않는다.
- 장치는 해당 스테이지 Devices에 실제 존재하는 종류만 한 번씩 안내한다. 불은 아군도 피해, 문은 주기 차단, 낙석은 준비 시 금색/눌러 사용이라는 기존 동작을 설명한다. 장치가 없는 스테이지에는 장치 설명을 붙이지 않는다.
- 하단은 준비 중 현재 도구/실패 이유/경로 색, 전투 중 궁극기/복구 대기, 클리어·실패 중 다음 행동으로 나눈다. 결과 단계에는 이전 배치 실패 문구·특수 적·장치 조작 설명을 붙이지 않는다. 기존의 모든 규칙/장치를 나열하는 문구와 별도 입구 개방 중복 문구를 제거한다.
- 배치 불가 이유가 있는 동안 하단에서는 그 이유를 우선하고 보조 특수 적/장치 설명을 잠시 생략한다. 가능한 위치로 옮기면 해당 웨이브 설명이 돌아온다.
- 왼쪽의 실제 웨이브 성과/보상 및 저장 실패 문구는 건드리지 않는다. 상단 기믹 제목도 유지한다.

## 책임과 수명

Code.UI.Stages.StageBriefingPresenter가 데이터 해석/문구를 맡고 HUD는 배치한다. 정의/웨이브가 바뀔 때만 입구/규칙/장치 문자열을 갱신해 반복 표시에서 목록/클래스를 새로 만들지 않는다. HUD의 EnsureRuntimeState가 캐시 유실 시 표시 클래스를 복구한다. 게임 데이터나 SO를 수정하지 않으며 새 정적 상태/검색/저장 필드를 추가하지 않는다.

맵/장치·적 편성/피해·속도·금화/보상·편성/저장 규칙은 유지한다. 검증은 신규 C#을 명시적으로 포함한 Runtime/Editor 코드 빌드와 가능한 편집 상태의 Unity 재컴파일/콘솔 읽기까지만 한다. 실제 표시·입구 개방/전투/저장 왕복과 테스트 러너는 실행하지 않는다.
