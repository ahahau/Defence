# 스테이지 준비·배치 조작 다듬기

2026-10-29 사용자 승인: 실제 크기의 배치 미리보기, 정확한 가능/불가 표시, 구체적인 실패 이유, 현재 선택 도구 구분과 우클릭 취소를 구현한다. 기존 설치/결제/환급 규칙과 수치·편성/저장 형식은 유지한다. 테스트·플레이 모드·밸런스 실측은 실행하지 않는다.

## 표시안

```text
편성에 없는 종류       [편성 추가]
편성에 포함된 종류     [배치 선택]
지금 배치하는 종류     [배치 중] ← 이 도구만 선택 테두리

유닛/바리케이드: 1×1 커서
2×2 함정:      2×2 커서(왼쪽 아래 기준, 실제 설치 중심과 일치)
가능: 초록 / 불가: 빨강 / 철거 대상: 호박색
불가 안내: 벽·맵 밖 / 설치 제한 / 코어·문·장치 / 점유 / 편성·해금 / 금화 부족

우클릭 → 도구 없음 · 편성은 그대로 유지
도구 없음 → 커서 숨김 · 지도 왼쪽 클릭으로 구매/철거하지 않음
```

기존 좌측 편성 목록과 하단 도구 안내를 그대로 쓴다. 새 패널/씬 배선/에셋은 추가하지 않는다. ESC는 기존 UiEscapeRouter에 맡기며 변경하지 않는다. 설정/팝업 중에는 지도 입력과 커서를 막는다.

## 책임 분리

- StagePlacement.Check는 설치 가능 여부/앵커/전체 차지 칸/비용/실패 이유를 값 타입 StagePlacementCheck로 반환한다. 조회는 결제·배치·메시지·저장을 변경하지 않는다. TryPlace는 같은 Check 결과를 확인한 뒤 기존 Create/Pay를 실행한다.
- StagePlacement.CheckDemolition은 실제 철거 대상의 범위와 앵커를 반환한다. 비어 있거나 이미 파괴된 대상을 표시하지 않는다. 철거 실행도 이를 확인하며 환급 비율/금액 계산은 기존대로 유지한다.
- Code.UI.Stages.StagePlacementTool이 도구 선택/우클릭 취소/커서 크기와 중심/맵 클릭을 맡는다. StageHudView에는 이벤트 연결과 화면 표시만 추가하고 기존 설치 판단 코드는 제거한다. 객체는 Awake에서 한 번 만들며 커서 갱신에 새 클래스/목록을 만들지 않는다.
- 편성 행은 편성 포함 여부와 현재 배치 선택을 구분한다. 배치 실패 메시지는 StagePlacement가 정한 이유를 그대로 표시하고 HUD의 일반 문구로 덮지 않는다. 마우스 이동은 자동 저장을 요청하지 않으며 실제 구매/철거 시 기존 저장 흐름을 유지한다.

## 범위와 검증

전체 면적을 확인해 겹침/맵 밖/예약 칸을 표시하며, 완전 경로 차단 여부는 기존 설치 허용 규칙을 유지한다. 준비 단계의 일시정지 중 편집은 기존대로 가능하다. 전투 중 배치/철거는 허용하지 않는다. 신규 C# 파일이 있어도 현재 사용자 금지가 우선하므로 소스 빌드/Unity 재컴파일과 정적 참조 검토만 하고 테스트 러너/플레이/모의 입력을 실행하지 않는다.


## 반영 결과

StagePlacementCheck(기본값 불가인 값 타입)와 StagePlacementTool을 추가했다. Check/TryPlace가 같은 면적/편성/해금/예약/점유/금화 판정을 사용하고 실패 이유를 한 번 알린다. CheckDemolition과 실제 철거가 이미 파괴된 대상을 건너뛰며, TrapAnchor는 기존 저장 좌표 계산과 공유한다. 결제/환급 수치·저장 형식은 변경하지 않았다.

StageHudView의 기존 한 칸 커서/간이 가능 판정/일반 실패 문구를 제거하고 도구에 위임했다. 커서는 실제 앵커·크기에 맞추며 불가 사유를 하단에 표시한다. 편성 행의 [배치 중]·금색 테두리는 현재 도구에만 적용한다. 우클릭은 도구만 해제하고 편성을 변경하지 않는다. 설정/팝업은 지도 입력을 막으며 ESC는 기존 라우터가 담당한다. 기존 최초 바리케이드 선택 동작은 유지한다.

Runtime/Editor 빌드·Unity 재컴파일 오류 0을 확인했다. 신규 C# 2개(.meta·UI/Stages 폴더 메타는 Unity 생성)가 있으나 사용자 금지에 따라 테스트 러너·플레이·모의 입력·밸런스 실측을 실행하지 않았다. 실제 마우스 조작/화면의 가독성은 미검증이다. 씬/프리팹/수치/사용자 저장 파일은 수정하지 않았다. 코드 변경 전 백업과 이번 작업만의 차이·빌드/재컴파일 근거는 tmp/stage-placement-polish-20261029에 남긴다.
