2026-10-28 사용자 요청: 한 스테이지에 가져갈 유닛·함정을 제한하고 게임 클리어 보상으로 업그레이드한다. 스테이지 진행 문맥에 맞춰 클리어 보상은 스테이지 완료 보상으로 해석한다. [스테이지 진행](StageDefenseDesign.md) · [종합 기획](../DungeonEconomyDesign.md).

## 2026-10-28 현재 구현 반영

사용자가 지금까지 확정한 규칙의 구현과 미정 수치의 임시 설정을 승인했다. 새 `Assets/00.Scenes/StageDefense.unity`와 `Assets/01.Code/Stages/`에 초기 런타임을 작성했다. 타이틀 새 게임은 빌드 목록에 있는 StageDefense로 들어가고, 기존 이어하기는 SampleScene을 유지한다. 기존 런/메타 파일을 삭제하거나 변환하지 않는다.

- 고정 맵/문/코어·기믹·웨이브 에셋, 열린 길 우선 내부 네 방향 A*, 완전 차단 시 이동+파괴 예상 시간, 현재 유닛 위치 점유·사망 시 해제, 제한 추적/복귀·근거리 교전을 연결했다.
- 코어 도달 피해 한 번 후 제거(처치 보상 없음), 웨이브 사이 코어 체력 유지, 코어 0 실패와 처음부터 재편성, 부하 웨이브 종료 복구를 연결했다.
- 체력/무피격 후 회복·파괴/즉시 철거와 실제 지불액 기준 1회 환급, 준비 전용 구매/배치/철거를 연결했다.
- 공용 편성·허용 종류 검증·영구 피해 강화·초회 클리어 보상·다음 스테이지 해금을 연결했다. 처음 배치 전에만 해당 판에 적용할 강화를 구입할 수 있으며 결과 화면에서는 다음 공략을 위해 강화할 수 있다. 편성은 첫 웨이브 전까지 변경 가능하되 이미 배치한 종류를 빼려면 먼저 회수/철거해야 한다.
- 새 프로필 `defence-stage-profile-v1.json`은 단계 해금/강화/재화를 별도 버전/원본/백업으로 보존한다. 보상/강화는 파일 교체 성공 후 상태를 확정하고, 읽기 실패 시 원본/백업을 보호한다. 스테이지 도중 체크포인트 이어하기는 아직 제공하지 않는다. 이번 작성 과정에서 사용자 프로필을 생성/수정하지 않았다.
- 기존 프리팹의 체력·스탯·평타·애니메이션·함정 효과를 재사용한다. 구 BattleAgent/Behavior 그래프의 자동 이동은 끄고 StageActor가 스킬 자동/궁극기 수동 시전을 맡는다. SkillCaster는 쿨다운/표시와 실제 효과 실행에 사용한다. 보스/호위·설정/배속·문/칸/표식 적·환경 장치도 반영했다. 유물/명령·파티 동행의 전체 이전과 스테이지 중 체크포인트는 후속이다. 구 SampleScene은 보존한다.
- 복귀 칸이 막히면 추적 반경 안의 가까운 도달 가능한 빈 칸에서 대기하고 자리가 열리면 복귀한다. 이동 경로는 0.25초마다 재평가하고 동료와 최소 간격을 둔다. 파괴 시간은 체력과 방어 적용 후 적 피해/공격 간격을 사용하며 치명타/동료 협공 예측은 생략한 초기 근사치다.

플레이와 테스트를 실행한 완료 근거는 없다. 런타임/에디터 코드 빌드와 Unity 재컴파일 오류 0, 저장된 새 씬의 누락 스크립트/편성 행 참조 0만 확인했다. 상세 구현/임시 수치는 [런타임 구현 기록](StageRuntimeImplementationDesign.md)을 따른다.

## 확정 방향과 기준안

사용자 확정 방향은 제한된 편성으로 스테이지를 공략하고 클리어 보상으로 다음 공략을 위한 영구 업그레이드를 하는 것이다. 아래의 종류 수 제한·공용 슬롯·전용 강화 재화는 이를 구체화하는 기준안이며, 슬롯 수·별도 개체 제한·보상/강화 수치를 확정한 것은 아니다. 현재 구현과 임시 수치는 위 반영 현황과 런타임 구현 기록을 따른다.

## 고정 스테이지 후속 결정

스테이지 지형·던전문·코어는 미리 정해져 있고 지형 파기는 제공하지 않는다. 바리케이드는 편성 슬롯을 사용하지 않는 기본 도구이며 금화로 설치한다. 구매·배치·철거는 준비 단계 전용이다. 유닛/바리케이드 차단·바닥 함정 통행·A*와 파괴 경로·코어 도달 처리는 [공간 설계](DungeonPathDesign.md)를 따른다. 아래 편성 슬롯 제한은 부하/함정에 적용하며 바리케이드를 포함시키는 것으로 읽지 않는다.

## 스테이지 편성

- 해금된 부하·함정 전체 중에서 이번 스테이지에 사용할 종류를 고른다. 우선 제한 단위는 배치 개체 수가 아니라 가져갈 종류 수로 설계한다.
- 부하·함정이 같은 편성 슬롯을 나누어 쓰는 안을 우선 추천한다. 부하 중심/함정 중심/혼합 구성 자체가 선택이 된다. 부하 슬롯과 함정 슬롯을 분리하는 대안도 가능하며 배분 방식과 총 슬롯 수는 구현 전에 확정한다.
- 같은 종류를 여러 슬롯에 넣어 개체 수나 성능을 늘리지는 않는 안이다. 예를 들어 근접 부하·원거리 부하·가시 함정·감속 함정을 고르면, 그 종류만 이번 판의 구매/배치 목록에 나타난다. 이 예시는 슬롯 수 확정이 아니다.
- 가져간 종류를 실제로 배치할 때는 해당 스테이지의 금화와 유효한 배치 공간이 필요하다. 같은 종류를 여러 개 설치하는 것과 가져갈 종류 수는 별개다. 2026-10-28 확정: 별도 전체 개체 제한은 두지 않고 금화로만 제한한다. 스테이지에 메인 유닛은 없다.
- 맵·침입자/기믹 예고를 확인하고 첫 웨이브 시작 전에 편성을 확정한 뒤, 해당 스테이지가 끝날 때까지 고정하는 안을 추천한다. 배치물을 회수하거나 금화를 환불받아도 가져가지 않은 종류로 교체할 수 없다.
- 해금은 선택할 자격이고, 편성은 이번 판에 사용하는 선택이다. 해금된 모든 종류를 즉시 설치 목록에 노출하지 않는다.

## 실패와 재편성

코어 체력 0으로 실패하면 해당 스테이지 처음부터 재도전하고 편성을 다시 선택할 수 있다. 실패한 웨이브 상태를 복원하는 방식은 아니다. 재도전은 스테이지 시작 자원/코어/배치 상태를 사용하고, 해금과 이미 획득한 영구 강화는 유지한다. 2026-10-28 확정: 실패 보상은 없다. → 2026-11-02 사용자 결정으로 변경: 아직 깨지 못한 스테이지에서 코어 0 패배 때 끝까지 막은 웨이브 1개당 강화 재화 1, 상한 초회 클리어 보상의 절반(내림). 수치는 임시(`StageCatalogSO.FailureRewardPerWave`·`FailureRewardCapRatio`)이며 현재 초회 보상 3에서는 상한 1이다.

## 클리어 보상과 강화

- 스테이지 클리어 보상으로 부하·함정을 영구 업그레이드하고 이후 스테이지에도 적용한다. 스테이지 금화·배치 초기화와 별개로 해금·강화 진행은 보존한다.
- 금화는 판 안의 구매/배치 자원으로 남기고, 클리어 보상용 강화 재화 하나를 따로 두는 안을 추천한다. 여러 재료·일일 수입·유지비·대출을 다시 만들지 않는다. 재화 명칭·지급량·가격은 미정이다.
- 강화는 스테이지 밖에서 대상 부하/함정을 골라 직접 진행하는 단순 방식으로 시작하는 안이다. 강화 트리·분기·무작위 옵션·상점 재고를 필수로 추가하지 않는다.
- 부하는 체력/공격 또는 고유 역할 성능, 함정은 피해/재사용 대기시간 또는 고유 효과를 강화 후보로 둔다. 모두 일괄 증가시키는 규칙이나 구체 수치는 확정하지 않는다.
- 2026-10-28 확정: 보상은 초회 클리어만 지급하고 재클리어·실패 보상과 평가/도전 보상은 두지 않는다. (2026-11-02: 실패 보상만 위 결정으로 바뀌었다. 재클리어·평가/도전 보상은 그대로 없다.)
- 2026-10-28 확정: 강화 환불은 없다. 해금은 정해진 스테이지 첫 클리어로 자동 지급한다. 편성 슬롯은 4칸에서 시작해 2·4 스테이지 첫 클리어에 +1씩, 최대 6칸. 부하 9종·함정 7종의 시작 구성과 스테이지별 해금표는 [StageDefenseDesign.md](StageDefenseDesign.md) "해금 배정".
- 강화 단계/상한, 신규 종류 해금 방식과 슬롯 확장 여부는 미정이다. 무제한 반복 보상이나 자동 슬롯 확장을 기본값으로 넣지 않는다.
- 스테이지를 진행하는 동안 적용 강화 수준은 고정하는 안이다. 기존 런의 유닛 경험치/레벨·일차 해금·주간 지원자 갱신을 영구 강화 규칙으로 그대로 사용하지 않는다. 각 시스템의 유지/대체는 구현 시 정한다.

## 플레이 흐름

```text
스테이지·침입 정보 확인 → 부하/함정 편성 → 금화로 구매·배치 → 웨이브 방어
→ 스테이지 클리어 → 보상 획득 → 영구 업그레이드 → 다음 스테이지 편성
```

웨이브 완료 보상은 판 안의 운영 금화, 스테이지 클리어 보상은 판 밖의 강화 진행이라는 경계로 설계한다. 중간 웨이브를 깼다고 영구 보상을 중복 지급하지 않는다.

## 구현 경계와 순서

1. 스테이지 데이터/진행 경계와 함께 해금 목록·선택 편성·영구 강화·스테이지 금화를 분리한다. 편성과 프로필 강화 저장은 기존 런 저장과 별도 수명으로 다룬다.
2. 편성 검증과 구매/설치 제한을 연결한다. 화면 후보 필터와 실제 설치 요청이 같은 허용 목록을 사용해야 한다.
3. 단일 맵/길·금고 생존·스테이지 클리어 판정을 연결한다.
4. 클리어 보상 지급·영구 강화 구매·저장을 연결한다. 결과 창 재열기/계속 버튼 연타/불러오기로 보상이 다시 지급되지 않도록 완료 기록과 지급을 함께 관리한다.
5. 편성/강화 UI·튜토리얼을 연결한다. 기존 저장 처리와 수치는 실제 변경 범위를 설명한 뒤 확정한다.

편성/클리어 보상/영구 강화의 초기 구현 범위는 위 반영 현황과 런타임 구현 기록을 따른다. 아래 기획의 미정 정책을 임시 수치와 혼동하지 않는다. 테스트·플레이·밸런스 실측은 실행하지 않았다.
