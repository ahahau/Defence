# 긴 던전 홀과 스테이지 타일 정리

2026-10-29 사용자 승인: Dungeon Warfare·Orcs Must Die를 참고해 타일을 정돈하고 7개 스테이지를 39×15칸 안팎의 긴 홀로 확장한다. 입구→배치 공간→협소 통로→방어 홀→코어를 기본 흐름으로 삼고 각 스테이지의 문 수/개방 시점·기믹 종류와 기존 전투/금화 수치를 유지한다. 테스트·플레이·밸런스 실측은 실행하지 않는다.

## 실제 에셋 진단

기존 Dark Castle 스프라이트는 16×16px·16PPU라 기본 한 칸이 1유닛이다. StageMapView는 격자를 0.625유닛으로 만들고 CellSize/0.625 배율을 적용해 타일 그림이 논리 칸보다 1.6배 크게 겹쳤다. 원본/공용 RuleTile은 변경하지 않고 스테이지 격자를 1유닛·배율 CellSize로 맞춘다. 벽은 바닥 위쪽에 3줄이 있어야 면 하단/상단/난간 조각이 이어진다.

## 렌더링

StageMapPainter가 바닥과 주변 벽 띠(좌우/아래 1·위 3칸)를 칠한다. 같은 주 타일맵 안에서 바닥/벽 RuleTile의 이웃 판정을 유지한다. 별도 하부 바닥층은 벽의 투명한 부분을 받치고, 장식층은 벽면 횃불/작은 장식만 배치한다. 문틀은 기존 에셋을 사용하며 코어·문·캐릭터 좌표와 논리 격자를 일치시킨다. 원래 룰 타일의 바닥 변화/벽 모서리 조각을 재사용한다. 원본 외부 팩/공용 타일과 SampleScene은 건드리지 않는다.

## 배치와 이동

7개 모두 39×15칸, 상부 외곽 3줄·하부/측면 외곽 1줄을 기본으로 한다. 넓은 홀 사이 통로는 대체로 3~4칸 폭으로 두어 2×2 함정을 설치할 여지를 남긴다. 실제 에셋을 기준으로 1은 한 문/두 굴곡의 기본 홀, 2는 단계 개방하는 두 문 합류, 3은 설치 제한/강화 칸과 중앙 우회, 4는 불/문이 있는 굴곡 통로, 5는 두 문과 복수 통로, 6은 세 문/낙석과 병렬 통로, 7은 세 문·칸/장치가 있는 긴 최종 홀로 구분한다. 기존 문 개방/장치 설정은 유지하고 좌표만 새 공간에 배치한다. 문 모두 닫힘에서도 코어로 통하는 고정 바닥을 남긴다.

맵 이동 거리는 길어지므로 기존과 체감 난이도가 달라질 수 있다. 스폰/적 체력·속도·금화/가격/보상 등 수치는 조정하지 않으며 밸런스를 검증한 것으로 기록하지 않는다.

## 카메라와 편집

기존 좌측 편성 HUD를 피하는 화면 영역에 맵 전체를 맞춘다. 카메라/코어/문/타일 배치를 같은 작성 API로 갱신하고 에디트 모드 씬에도 첫 스테이지를 저장해 실제 편집 상태로 보인다. Unity CLI와 Editor API를 사용하고 YAML은 직접 쓰지 않는다. 미저장 씬은 덮어쓰지 않는다.

## 저장과 검증 범위

지형/문/코어 변경은 기존 준비 체크포인트 서명과 호환되지 않는다. 기존 파일은 삭제·변환하지 않고 현재 실패 시 저장 차단을 유지한다. 영구 강화는 유지하고 새 게임으로 변경 맵을 시작한다. 확인은 소스 빌드/재컴파일·작성 좌표/타일 크기·에디트 모드 정지 화면 확인까지만 한다. 테스트 러너/플레이/전투 시뮬레이션은 실행하지 않는다.

참고: [Dungeon Warfare](https://store.steampowered.com/app/355980/Dungeon_Warfare/)의 수제 스테이지/함정 동선, [Orcs Must Die! 3](https://robotentertainment.com/omd3)의 방어 공간/함정 배치를 참고한 프로젝트용 설계다.


## 반영 결과

- StageMapPainter·StageHallLayout·StageHallBuilder를 분리해 추가했다. StageMapView의 격자/스프라이트 1:1 비율을 고쳤고, 바닥 하부/벽 장식층을 연결했다. 기존 작성기도 새 홀/동일한 PaintLayout을 사용한다. 저장된 지형의 커서는 숨기며 실행 시 기존 HUD 입력이 켠다.
- 7개 에셋을 39×15로 작성했다. 문 수는 1/2/1/1/2/3/3, 장치 수는 0/0/0/3/0/4/5다. 2·6·7의 문 개방 시점과 3·7의 설치 제한 8칸/강화 6칸을 유지한다. 에셋 차이에서 지형/문/코어/장치 좌표 이외 변경이 없음을 확인했다.
- 작성 전에 TryValidate와 모든 환경 문 닫힘의 고정 경로 검사를 거친다. 첫 7스테이지 초안의 접속 벽을 이 단계에서 찾아 실제 에셋 변경 전에 수정했다. 이 확인은 에디트 모드 작성 데이터 검사이며 전투/플레이 테스트가 아니다.
- 미저장 SampleScene 때문에 Single 씬 전환을 중단하고 Additive로 StageDefense를 작성했다. SampleScene은 저장/폐기하지 않았다. StageDefense만 저장했으며 두 씬이 함께 열려 있으면 편집기 지형/조명이 겹칠 수 있다. 정지 도해는 스테이지 씬만 분리했다.
- Runtime/Editor 빌드와 Unity 재컴파일 오류 0. 테스트 러너·플레이·밸런스 실측은 미실행이다. 조명이 적용된 정지 캡처는 어두워, 별도 타일 도해는 임시 Unlit 재질로 기록하고 실제 재질 Sprite-Lit-Default/카메라를 복원했다. 실제 조명·전투 가독성은 플레이 검증하지 않았다. 지형 변경으로 이전 준비 저장은 새 게임이 필요하고 영구 프로필/사용자 저장 파일은 건드리지 않았다.
- 변경 전 스테이지/씬/소스·작업 차이·컴파일 로그·조명 제외 타일 도해: tmp/stage-halls-20261029. Unity API로 작성했으며 YAML 직접 편집은 하지 않았다.
