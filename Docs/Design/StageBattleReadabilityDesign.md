# 전투 상황 표시 다듬기

2026-10-29 사용자 승인: 코어 피격 강조/피해 표시/낮은 체력 경고, 바리케이드 손상·회복 상태와 파괴 위치 표시, 부하의 웨이브 종료 복구 대기 표시를 추가한다. 체력/피해/이동/환급/복구 시점과 저장 형식은 유지한다. 테스트·플레이·모의 전투는 실행하지 않는다.

## 표시안

```text
상단: 코어 3/10 [위험]  금화 ...  웨이브 ...  남은 적 ...  복구 대기 2
안내: 코어 피격 -2              ← 잠시 표시, 기존 저장 오류가 있으면 오류 우선
지도: 코어 자리 짧은 붉은 강조 / 파괴된 바리케이드 자리 짧은 X
바리케이드 체력바: 정상 초록 / 손상 호박색(낮으면 빨강) / 회복 중 파랑
쓰러진 부하 머리 위: 회색 = 표식 / 웨이브 종료 복구 시 즉시 숨김
```

기존 상단 상태·좌측 안내·하단 조작 안내와 배치 커서 스프라이트를 재사용한다. 새 패널/외부 에셋/사운드/전체 화면 섬광/카메라 흔들림은 추가하지 않는다. 부하와 적의 기존 사망/피격 포즈·스킬 반짝임에는 접근하지 않는다.

## 책임과 수명

- StageSession.CoreDamaged는 실제 코어 체력 감소량을 적 처리/패배 처리 후 알린다. 복원/스테이지 초기화로 체력이 바뀐 것은 피격으로 취급하지 않는다. UI가 없어도 게임 처리는 끝난다.
- 바리케이드 제거는 실제 파괴인지 철거인지 명시적으로 구분한다. 차단 해제·환급·비활성/파괴 처리를 마친 뒤 파괴 위치만 세션 이벤트로 알린다. 중복 제거 방지 플래그를 유지한다. 플레이어 철거에는 파괴 표시를 내지 않는다.
- StageBarricade의 회복 대기/회복 가능 상태는 기존 지연·회복률·체력·단계를 그대로 읽는 계산 프로퍼티다. StageHealthBar는 이를 색으로 표시한다. 회복량이나 시간을 바꾸지 않는다.
- Code.UI.Stages.StageBattleSignals는 신호를 받아 짧은 위치 강조와 안내를 표시하며 쓰러진 아군 수/표식을 갱신한다. 표시 스프라이트는 재사용하며 매 프레임 새 클래스/목록을 만들지 않는다. HUD OnEnable/OnDisable에서 구독/해제를 짝짓고 OnDestroy에서 만든 표시를 정리한다. 스테이지 보드가 바뀌면 이전 경고/위치/집계를 버린다.
- 부하 복구 대기 표식은 준비/전투 중 체력이 0인 아군에만 붙는다. 패배/클리어 상태에는 복구 약속을 표시하지 않는다. 웨이브 종료의 기존 Recover로 체력이 회복되면 다음 표시 갱신 때 사라진다.

## 표시용 임시 기준

코어/바리케이드의 낮은 체력 색 기준은 30%이며 표시만 달라진다. 코어 위치 강조 0.45초·피격 안내 1.2초, 파괴 위치 X 0.65초·안내 0.9초를 게임 시간으로 표시한다(일시정지 중 정지). 연속 코어 피해는 안내가 남은 동안 합산한다. 파괴 위치는 동시 8개까지 돌려 쓰며 피해/환급에는 영향을 주지 않는다. 표시 수치는 검증된 체감값이 아닌 초기 시각 설정이다.

## 검증 범위

소스/구독 수명/실제 처리 순서를 검토하고 Runtime/Editor 빌드·Unity 재컴파일 오류를 확인한다. 신규 C# 파일이 있어도 사용자 테스트 금지가 우선한다. 실제 전투·표시 타이밍·난전 가독성과 색 구분은 플레이 검증하지 않는다. 씬/프리팹/밸런스·사용자 저장 파일은 수정하지 않는다.


## 반영 결과

StageBattleSignals와 세션 이벤트를 연결했다. 코어 피해는 실제 체력 차이로 계산하고, 적 제거/패배 처리 뒤 알린다. 바리케이드도 차단 해제/환급/비활성·파괴를 마친 뒤 파괴 위치를 알리며 철거와 구분한다. 이 알림은 세션 변경/자동 저장을 발생시키지 않는다.

기존 커서 스프라이트를 이용한 위치 강조·X·회색 복구 대기 표식과 상단 대기 인원/코어 경고, 좌측 짧은 피격 안내를 추가했다. 저장 오류는 안내보다 우선한다. 기존 코어/캐릭터 그림·피격·사망·스킬 연출을 다시 칠하지 않는다. HUD가 구독/해제를 짝짓고 종료 시 표시 루트를 제거하며 이미 파괴된 표시 접근을 피한다. 보드 변경 시 이전 신호를 버린다. StageHealthBar만 바리케이드 회복 상태에 따라 색을 바꾼다.

Runtime/Editor 빌드·Unity 재컴파일 오류 0을 확인했다. 신규 C# 1개(.meta는 Unity 생성)가 있으나 테스트 러너/플레이/모의 전투/밸런스 실측은 실행하지 않았다. 실제 전투 화면/가독성·표시 타이밍은 미검증이다. 씬/프리팹/밸런스/사용자 저장·저장 형식 변경은 없다. 작업 전 코드 백업과 이번 작업만의 차이·컴파일 근거는 tmp/stage-battle-readability-20261029에 남긴다.

## 금고 위협 표시 (2026-11-02)

사용자 승인: UiVisualDesign 정보 우선순위 1번 "금고에 가까운 위협"을 실제 걸어서 남은 칸 기준으로 보인다.

- 전투 중 상단 상태 줄의 코어 항목에 " · 적 N칸"(가장 가까운 적)을 붙인다. 예: "코어 7/10 · 적 4칸". 5칸(`StageCoreThreat.DangerCells`, 임시) 안이면 코어 항목 전체가 위험색이고 코어 칸이 옅게 맥동한다. 피격 강조가 더 진하면 피격 강조가 이긴다. 준비·결과 단계에는 보이지 않는다.
- `StageCoreThreat`가 보드가 바뀔 때 코어에서 상하좌우로 바닥 칸 거리를 한 번 퍼뜨리고(적 길찾기와 같은 4방향), 0.25초(게임 시간)마다 적 위치만 다시 본다. 지형만 막힘이다. 바리케이드·부하는 부술 수 있고 여닫는 문은 곧 다시 열리므로 넣지 않는다. `StageBattleSignals`가 이것을 갖고 코어 항목 글·코어 맥동을 맡는다.
- 리뷰 보완(2026-11-02): 처음에는 남은 적 뒤에 "코어까지 N칸"을 따로 붙였으나 보스·정예 웨이브에서 상태 줄이 16pt에서 줄을 넘을 수 있어 코어 항목에 합쳤다. 닫힌 문을 막힘으로 보면 문 뒤의 가까운 적이 빠져 표시가 깜빡여 지형만 막힘으로 바꿨다.
- 전투·이동·저장·씬은 바꾸지 않았다. Runtime/Editor 빌드·Unity 재컴파일·콘솔 오류 0. 테스트·플레이를 하지 않아 실제 가독성·맥동 세기·5칸이 알맞은지는 미검증이다.
