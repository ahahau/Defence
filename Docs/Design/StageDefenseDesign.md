# 스테이지형 금고 방어

2026-10-28 사용자 승인: Dungeon Warfare처럼 스테이지 형식으로 간다. 한 스테이지는 하나의 큰 연속 맵이며 지형/입구/금고와 편집 가능 영역·웨이브·기믹을 정의한다. 준비→여러 웨이브 방어→클리어 보상→다음 스테이지다. 스테이지를 넘기면 금화·배치는 초기화하고 해금한 부하/함정 선택지는 유지한다.

## 2026-10-28 현재 구현 반영

사용자가 지금까지 확정한 규칙의 구현과 미정 수치의 임시 설정을 승인했다. 새 `Assets/00.Scenes/StageDefense.unity`와 `Assets/01.Code/Stages/`에 초기 런타임을 작성했다. 타이틀 새 게임은 빌드 목록에 있는 StageDefense로 들어가고, 이어하기는 스테이지 준비 저장을 우선하고 없을 때 기존 SampleScene 런을 유지한다. 기존 런/메타 파일을 삭제하거나 변환하지 않는다.

- 고정 맵/문/코어·기믹·웨이브 에셋, 열린 길 우선 내부 네 방향 A*, 완전 차단 시 이동+파괴 예상 시간, 현재 유닛 위치 점유·사망 시 해제, 제한 추적/복귀·근거리 교전을 연결했다.
- 코어 도달 피해 한 번 후 제거(처치 보상 없음), 웨이브 사이 코어 체력 유지, 코어 0 실패와 처음부터 재편성, 부하 웨이브 종료 복구를 연결했다.
- 체력/무피격 후 회복·파괴/즉시 철거와 실제 지불액 기준 1회 환급, 준비 전용 구매/배치/철거를 연결했다.
- 공용 편성·허용 종류 검증·영구 피해 강화·초회 클리어 보상·다음 스테이지 해금을 연결했다. 처음 배치 전에만 해당 판에 적용할 강화를 구입할 수 있으며 결과 화면에서는 다음 공략을 위해 강화할 수 있다. 편성은 첫 웨이브 전까지 변경 가능하되 이미 배치한 종류를 빼려면 먼저 회수/철거해야 한다.
- 새 프로필 `defence-stage-profile-v1.json`은 단계 해금/강화/재화를 별도 버전/원본/백업으로 보존한다. 보상/강화는 파일 교체 성공 후 상태를 확정하고, 읽기 실패 시 원본/백업을 보호한다. 준비 단계 체크포인트 이어하기는 별도 파일로 추가했다. 전투 도중 종료하면 마지막 준비부터 해당 웨이브를 다시 시작한다. 상세 StageCheckpointDesign.md. 이번 작성 과정에서 사용자 프로필을 생성/수정하지 않았다.
- 기존 프리팹의 체력·스탯·평타·애니메이션·함정 효과를 재사용한다. 구 BattleAgent/Behavior 그래프의 자동 이동은 끄고 StageActor가 스킬 자동/궁극기 수동 시전을 맡는다. SkillCaster는 쿨다운/표시와 실제 효과 실행에 사용한다. 보스/호위·설정/배속·문/칸/표식 적·환경 장치도 반영했다. 유물·부하 명령·파티 동행은 이후 구현했다([고정 스테이지 구현](StageRuntimeImplementationDesign.md)). 구 SampleScene은 보존한다.
- 복귀 칸이 막히면 추적 반경 안의 가까운 도달 가능한 빈 칸에서 대기하고 자리가 열리면 복귀한다. 이동 경로는 0.25초마다 재평가하고 동료와 최소 간격을 둔다. 파괴 시간은 체력과 방어 적용 후 적 피해/공격 간격을 사용하며 치명타/동료 협공 예측은 생략한 초기 근사치다.

플레이와 테스트를 실행한 완료 근거는 없다. 런타임/에디터 코드 빌드와 Unity 재컴파일 오류 0, 저장된 새 씬의 누락 스크립트/편성 행 참조 0만 확인했다. 상세 구현/임시 수치는 [런타임 구현 기록](StageRuntimeImplementationDesign.md)을 따른다.

스테이지별 기믹은 좁은 통로/교전 공간·복수 입구·추가 통로 개방·설치 제한·침입 방향 변화 같은 배치 문제로 만든다. 고정 지형과 편집 가능 땅을 구분해 모든 기믹을 임의 길 편집으로 무력화하지 않게 한다. 맵/입구/금고 좌표·웨이브 수·클리어 판정·초기 자원 수치는 각 스테이지 데이터로 정하며 이번 승인으로 임의 새 수치를 만들지 않는다.

## 고정 스테이지·코어·파괴 이동 후속 확정

2026-10-28 사용자와 질문으로 확정: 스테이지 지형·던전문·코어는 미리 정해져 있고 스테이지별 기믹이 있다. 지형 파기 없이 배치로 동선을 바꾼다. 바리케이드와 유닛은 길을 차단하고 바닥 함정은 통행 가능하다. 적은 A*로 코어까지 빠른 열린 경로를 우선하며 완전 차단 시 이동+파괴 예상 시간이 최소인 경로를 뚫는다. 코어 도달 시 피해 한 번 후 사라진다. 바리케이드는 기본 도구로 편성 슬롯 없이 금화로 설치하고, 체력과 무피격 일정 시간 후 자동 회복이 있다. 파괴 시 길이 열리고 실제 설치비 일부를 돌려받는다. 준비 단계에서 즉시 철거해도 실제 설치비 일부를 돌려받으며 각 환급률은 미정이다. 쓰러진 유닛 자리는 즉시 통행 가능해지고 웨이브 종료 후 유닛이 복구한다. 구매/배치/철거는 준비 단계 전용이다.

세부 확정/질문 대기 항목은 [고정 맵·차단/파괴 설계](DungeonPathDesign.md)를 따른다. 기존 자유 길 파기·열린 경로 부재만으로 시작 거절·금고 위치 미정 기준은 이 결정으로 대체한다. 2026-11-02 기준 고정 맵·차단/파괴 경로는 구현돼 있다([고정 스테이지 구현](StageRuntimeImplementationDesign.md)).

## 유닛 주둔과 코어 체력 후속 확정

유닛은 배치 지점 주변의 짧은 범위만 추적하고 전투 후 배치 지점으로 복귀한다. 이동 중에는 현재 위치만 통행을 막고 원래 배치 지점은 열린다. 정확한 거리·복귀 불가 시 처리는 아직 미정이다. 코어의 남은 체력은 같은 스테이지의 웨이브 사이에 그대로 유지되며 새 스테이지에 들어갈 때 초기화한다. 코어의 웨이브 간 자동 회복은 없다. 코어 체력 0이면 패배하며 해당 스테이지 처음부터 편성을 다시 고를 수 있다. 코어/판 안 금화/배치는 초기화하되 해금·영구 강화는 유지한다. 실패 보상은 아래 표의 2026-11-02 결정을 따른다. 적은 열린 경로가 있어도 가까운 아군이 교전 범위에 들어오면 싸운 뒤 코어로 이동한다. 코어 도달 피해는 적 종류별 별도 값으로 지정하고 현재 공격력과 연동하지 않는다. 2026-11-02 기준 구현돼 있다(거리 수치는 임시).

## 2026-10-28 스테이지 구성 확정

사용자와 질문으로 정했다. 기믹은 하나씩 소개한 뒤 조합하고, 보스는 기믹에 어울리게 붙인다. 스테이지마다 마지막 웨이브는 보스와 호위 소수다. 웨이브 수는 연습 스테이지 3에서 시작해 뒤로 갈수록 늘려 마지막은 5~6이다(정확한 수는 수치 작업 때 정함). 편성 슬롯은 4칸에서 시작해 2·4 스테이지 첫 클리어 때 하나씩 늘어 6칸이 된다.

| 스테이지 | 기믹 | 보스 | 첫 클리어 |
|---|---|---|---|
| 1 | 없음(연습: 문 하나, 배치·바리케이드·경로 미리보기 익히기) | 탐욕의 기사 | |
| 2 | 도중에 열리는 문 | 기마 두목 | 슬롯 +1 |
| 3 | 설치 불가 칸·효과가 커지는 칸 | 왕국 기사단장 | |
| 4 | 환경 장치 | 대마법사 | 슬롯 +1 |
| 5 | 적 특수 규칙 | 사냥꾼 두목 | |
| 6 | 조합(문 + 환경 장치) | 오크 대족장 | |
| 7 | 조합(전부) | 토벌대장 | |

보스 이름은 데이터(`EnemyDataSO.Name`) 기준이다. 질문 때 쓴 산적 기수·기사단장·오크 전투족장·진압자는 각각 기마 두목·왕국 기사단장·오크 대족장·토벌대장(Boss_BanditRider·KnightCommander·OrcWarchief·Subjugator)이다.

- 적 특수 규칙: 바리케이드 뛰어넘기, 교전 무시 돌진(아군을 상대하지 않고 코어로만 감). 함정 해제·함정 우회는 넣지 않는다.
- 환경 장치: 주기적 불 구멍(적·아군 모두 피해), 열고 닫히는 문(경로가 바뀜, 미리보기는 두 상태를 보여줌), 플레이어가 켜는 장치(전투 중 눌러 쓰는 낙석·수문 등, 재사용 대기 있음). 적 강화 제단은 넣지 않는다.
- 지금 있는 임시 Stage_01(갈림길)·Stage_02(문 두 곳 번갈아)는 이 구성 전의 실행용이다. 7개로 다시 만들 때 대체한다.
- 기믹을 어느 웨이브에 켜는지, 스테이지별 맵 모양·크기는 미정이다.
- 2026-10-28 기믹 세부 확정: 도중에 열리는 문은 정해진 웨이브부터 열리고 준비 단계에 예고한다. 설치 불가 칸·강화 칸은 바닥 색으로 항상 보인다. 강화 칸 함정은 피해 +50%. 적 특수 규칙은 일부 적에게만 머리 위 표식으로 붙인다. 환경 장치는 맵에 고정하고 4스테이지(불 구멍·여닫는 문)부터 넣고 6·7스테이지에 플레이어가 켜는 장치를 더한다. 구현 범위는 `StageRuntimeImplementationDesign.md` "기믹" 절.

### 해금 배정 (2026-10-28 확정)

부하는 역할이 뚜렷한 9종만 쓴다: 해골 방패병, 해골 검사, 오크 철퇴병, 뼈 궁수, 해골 저격수, 해골 주술사, 오크 주술사, 늑대 기수, 망령 암살귀. 독/피 해골 검사(색 변형)·해골 낫잡이·해골 도끼병·해골 기병은 스테이지에 쓰지 않는다(데이터는 지우지 않음). 함정은 7종 모두 쓴다. 괄호 안 역할은 질문 때 이름으로 붙인 설명이며 데이터로 확인하지 않았다.

시작 구성은 슬롯 수와 같은 4개라 1스테이지에서는 고를 것 없이 전부 들고 간다. 첫 클리어마다 다음 스테이지 기믹에 대비할 종류를 푼다(3/2/2/2/2/1, 6스테이지 클리어로 전부 풀림, 7 클리어는 해금 없음).

| 시점 | 풀리는 것 | 대비하는 다음 기믹 |
|---|---|---|
| 시작 | 해골 방패병, 해골 검사, 속박 수정, 불 화로 | |
| 1 클리어 | 늑대 기수, 뼈 궁수, 마력 수정 | 2 도중에 열리는 문 |
| 2 클리어(+슬롯) | 충격 수정, 핏빛 웅덩이 | 3 설치 불가·강화 칸 |
| 3 클리어 | 해골 주술사, 오크 철퇴병 | 4 환경 장치 |
| 4 클리어(+슬롯) | 해골 저격수, 노출 수정 | 5 바리케이드 넘기·돌진 |
| 5 클리어 | 오크 주술사, 번개 구름 | 6 조합 |

지금 임시 카탈로그(시작 부하 2 + 함정 4, Stage_01 뒤 3종 해금)와 다르다. 7개 스테이지를 만들 때 이 표로 바꾼다.

## 편성과 클리어 성장 후속 방향

2026-10-28 추가 요청으로 스테이지에 가져갈 부하·함정을 제한하고 클리어 보상으로 영구 업그레이드한다. 해금·강화 진행은 스테이지 전환 뒤에도 유지한다. [편성/영구 강화 설계](StageLoadoutProgressionDesign.md)를 따른다. 가져갈 종류 수를 슬롯으로 제한하는 안을 우선하며, 공용/분리 슬롯·총 슬롯 수·별도 개체 제한·강화 재화/수치는 아직 미정이다. 이 문단의 당시 기획은 위 초기 구현 범위로 전환했으며, 미확정 정책과 구현 범위를 구분한다.

## 경영 제거 패치 범위

실제 코드에서 반복 비용/이자/청산·신용 판정과 파산·금고 예금 수익, 고용 시세/상인 누적 가격, 피로/부상/민심 정책·마력 충전/FIFO 부활, 시설 소비/큐·적 지갑/소문·관련 반복 사건과 UI 진입점을 분리한다. 기존 처치/웨이브 보상·구매/환불·공통 전투/저장 보호는 유지한다. 부하는 웨이브 종료 후 복구하는 단순 흐름으로 전환한다.

이번 승인으로 런타임 패치를 진행한다. 과거 저장/직렬화/에디터와 연결된 데이터 타입/공개 API는 즉시 물리 삭제하지 않고 기존 형식 읽기와 연결 정리용으로 남길 수 있다. 동작 중단과 파일 삭제를 구분해 기록한다. 신규 스테이지/단일 맵 코드가 아직 연결되지 않은 부분을 완료로 표시하지 않는다. 금고 생존/도달 세부·새 저장 버전/이전 런 호환은 구현 시 별도 명시하고 사용자 저장 파일을 직접 수정하지 않는다.

테스트·플레이·밸런스 실측 금지는 유지한다. 변경 코드와 에셋 연결에 필요한 컴파일만 수행하고 런타임 검증 결과로 주장하지 않는다.

## 2026-10-28 경영 축소 반영 현황

- 적용: 유지비/시설비·이자·청산·대출/신용/파산 실행을 중단하고 고용 정가·상인 기본 가격을 사용한다. 보상 이벤트는 즉시 지급하며 결과 보고서에서 재지급하지 않는다.
- 적용: 피로/부상 보정을 제거하고 배치 부하는 웨이브 종료에 전투 가능 상태로 복구한다. 마력 제한/전투 중 자동 부활과 유료 치료 진입점은 중단했다. 기존 메인 유닛 패배 흐름은 새 금고 목표를 연결할 때 전환한다.
- 적용: 적의 시설 소비·큐/귀환·금고 금화 약탈·파티 지갑/소문, 반복 경영 사건을 중단했다. 광산 자동 수입·예금 금고 입출금/이자도 중단했다. 기존 처치 보상은 유지한다.
- UI: 시설 설치 후보/진입점, HUD 부채·마력·부활/민심, 금융 탭과 고용/배치 시세·유지비/마력·피로/유료 치료 표기를 제거 또는 비활성화했다. 기존 UI 프리팹 세 개를 Unity API로 갱신했다.
- 보존: 이전 씬/에셋·저장과 연결된 타입·직렬화 필드·공개 API와 사용하지 않는 경영 헬퍼는 호환용으로 남아 있다. 모든 경영 소스 파일을 물리 삭제한 상태는 아니다. 사용자 저장 파일을 직접 수정하지 않았다.
- 당시 미구현(2026-11-02 기준 모두 StageDefense에 구현): 스테이지 데이터/선택/클리어 전환, 스테이지 간 금화·배치 초기화 및 해금 보존, 단일 격자 배치·국소 교전, 실제 코어 도달 피해/패배, 새 저장 버전. 기존 일차/방 그래프/일정 해금/주간 지원자 갱신과 메인 유닛·보스 패배 처리는 전환 전 구조다.
- 다음 순서: 스테이지 데이터와 진행/자원 경계·편성/강화 상태 분리 → 편성 허용 목록 → 단일 맵/길 → 금고 도달과 클리어/패배 → 클리어 보상/영구 강화·UI와 저장. 각 단계의 실제 변경 범위와 수치가 필요한 결정은 착수 전에 설명한다.

검증 범위는 런타임 C# 빌드와 Unity 재컴파일이다. 테스트·플레이 모드·프리뷰·밸런스 실측은 실행하지 않았다. 기능 정상 동작을 실측했다고 해석하지 않는다.
