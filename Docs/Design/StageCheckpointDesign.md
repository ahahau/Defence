# 스테이지 준비 단계 체크포인트

2026-10-28 사용자 승인: 준비 단계 자동 저장과 타이틀 이어하기(제안 1·2)를 구현한다. 테스트·플레이·밸런스 실측은 실행하지 않고 컴파일까지만 확인한다.

## 저장 계약

- `defence-stage-run-v1.json`과 `.bak`을 사용한다. 구 SampleScene 런·메타와 스테이지 영구 강화 파일은 수정/변환하지 않는다.
- 준비 단계의 스테이지 ID, 지형/문/코어 호환 서명, 다음 웨이브, 편성 잠금, 코어 체력, 금화, 편성 ID, 실제 설치비와 배치를 기록한다. 부하는 원래 배치점과 현재 위치·개체 상태·스킬 대기시간, 바리케이드는 체력/회복 지연·누적 소수, 함정은 내구도/지속·틱·재사용 시간을 보존한다.
- 웨이브 종료 후 복구가 끝난 준비 단계, 준비 조작 후 짧은 지연, 준비 중 주기적 저장, 전투 시작 직전, 준비 중 종료/비활성화에 저장한다. 전투 중에는 파일을 갱신하지 않는다. 전투 도중 종료하면 마지막 준비부터 해당 웨이브를 다시 시작한다. 환경 장치와 부하 궁극기 게이지는 기존 웨이브 종료 초기화 규칙을 따른다. 진행 중 스킬 지대/연출·일시적 상태이상 전체는 저장하지 않는다.
- 완결/패배/명시적 새 게임은 종료 마커를 먼저 기록해 과거 준비 백업이 부활하거나 늦은 저장이 재생성되지 않게 한다. 새 스테이지 시작은 기존 파일을 고유 보관 폴더에 복사한 뒤 새 저장을 시작한다. 보관 실패 시 기존 파일을 보호하고 새 저장을 막는다.
- 2026-11-02 지형 칸: 지형/문/코어 호환 서명은 지형 칸 문자(`StageCatalogSO.TerrainRules`)를 일반 바닥으로 바꿔 계산한다(`StageTerrain.NormalizeRow`). 지형을 더한 3~7스테이지의 기존 준비 저장도 이어할 수 있다. 대신 지금 지형이 막는 칸에 저장된 함정은 "함정이 지금 지형에서 설치할 수 없는 칸에 있습니다"로 거부하고, 바리케이드 체력 상한에 그 칸의 지형 배율(암반)을 곱한다.

## 복원과 오류 보호

2026-10-29 후속: 형식 읽기를 통과한 저장의 의미 검증 실패는 StageCheckpoint가 구체 원인을 반환한다. 맵 호환 서명이 다르면 "맵·설정이 변경됐습니다"와 타이틀의 새 게임 선택을 안내한다. 편성/배치/프로필·웨이브/코어·결과 요약의 오류도 구분하며 실패 시 저장 차단/원본·백업 보호는 유지한다. 파일 파싱/버전 검사를 통과하지 못한 경우의 원본/백업 읽기 안내는 기존 저장소 경로를 유지한다. 자동 새 게임·지형 변환·사용자 파일 변경은 하지 않는다. [실행/복원 안내 설계](StageEntryRecoveryDesign.md).

파일 버전/필수 목록·스테이지/선택지 ID·해금·편성 수·웨이브/체력/금화·배치 종류/좌표·함정 면적과 중복·실제 지불 금액·유한한 시간 값을 검증한 뒤 복원한다. 부하는 전투 후 이동/복귀 중일 수 있어 원래 자리와 현재 위치를 별도로 처리한다. 복원 설치는 재결제하지 않는다. 저장된 개체의 강화 단계가 현재 프로필과 다르면 거절한다.

원본은 임시 파일의 원자적 교체로 쓰며 원본을 먼저 지우지 않는다. 원본 파싱 실패 시 백업 복원을 시도하되 해당 실행의 이후 저장을 차단해 정상 백업을 손상된 원본으로 덮지 않는다. 의미 검증/복원 실패도 자동 저장을 차단하고 기존 파일을 유지한다. 명시적 새 게임만 보관 후 새 저장을 시작한다.

## 진입과 책임

타이틀 이어하기는 새 스테이지 파일만 연다. 2026-11-02 사용자 결정으로 스테이지 파일이 없을 때 구 런의 SampleScene을 열던 경로를 닫았다(구 런 파일은 보존). 스테이지 저장이 없으면 "이어하기"로 잠긴다. 새 게임도 스테이지만 시작하며, StageDefense가 빌드 목록에 없으면 구 런 파일을 지우고 SampleScene으로 가던 예외 경로 대신 오류 로그·실패음으로 멈춘다(리뷰 보완). 손상된 스테이지 파일도 복원 오류를 알릴 수 있도록 StageDefense로 보내며 조용히 새 판으로 덮지 않는다. 새 게임은 스테이지 진행만 종료 표시하고 영구 강화/구 런은 유지한다.

파일 입출력은 StageCheckpointStore, 캡처/검증/복원은 StageCheckpoint, 직렬화 형식은 StageCheckpointData/StageSavedPlacement가 맡는다. StageSession은 단계 경계와 저장 요청만 연결한다. 씬/프리팹/YAML·수치는 변경하지 않는다.


## 반영 결과 (2026-10-29)

웨이브 결과 요약 후속: v1에 선택 항목 hasWaveReport/waveReport를 추가했다. 명시적 존재 플래그가 없는 구 저장은 요약 없이 복원한다. 새 요약은 직전 완료 웨이브 번호·처치+도달 합계·코어 피해/잔여 체력·획득 금화의 정합성을 검증하고 준비 단계에만 저장한다. 전투 중 종료 시 마지막 준비 결과를 유지하며 종료 마커·원본/백업 보호·보상 확정 계약은 변경하지 않는다. 종료 결과 자체를 이어하기로 복구하지 않는다. [상세 설계](StageWaveResultDesign.md).

4개 저장 전용 C# 파일과 기존 스테이지/함정/스킬·타이틀/설정 연결을 작성했다. 준비 조작 후 0.35초 이내·준비 중 5초 간격·웨이브 시작 직전·타이틀 전환/종료 직전에 캡처한다. 전투 중 저장 요청은 무시한다. 씬 전환은 오브젝트 파괴 전에 저장하고 종료 뒤 재저장을 막는다. 설정의 구 런 경로는 기존대로 유지하며 스테이지 재시작 경로는 StageDefense로 연결했다(기존 씬에서는 해당 버튼을 숨긴다).

패배 또는 영구 프로필에 클리어 보상을 확정한 뒤 종료 마커를 쓴다. 보상 저장 실패 시 마지막 준비 체크포인트를 남겨, 재진입 후 마지막 웨이브부터 다시 시도할 수 있게 한다. 보상은 기존 Profile.TryClear의 초회 지급 판정을 유지한다. 다음 스테이지/재도전 시 종료된 파일을 보관한 뒤 새 체크포인트를 시작한다.

Runtime/Editor 순차 빌드·Unity 재컴파일 오류 0, 현재 편집기 콘솔 오류 0을 확인했다. 동시에 실행한 빌드의 공유 DLL 잠금 오류는 순차 빌드로 해소했다. 테스트 러너·플레이 모드·프리뷰·밸런스 실측과 실제 사용자 파일에 대한 저장/복원 실행은 하지 않았다. 스킬 지대/연출·일시적 상태이상 전체 복원은 이번 저장 계약에 포함되지 않는다. 기획·현재 요약을 동기화하고 근거/수정 전 코드/작업 차이는 tmp/stage-checkpoint-20261028에 남긴다.
